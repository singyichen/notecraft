# 第 1 週：機器學習簡介

*Introduction to Machine Learning*

## 課程資訊

《資料分析與機器學習》由陳慶永老師開授，第一堂課先講清楚課要怎麼上、要準備什麼，再進入機器學習本身。課名雖然叫「資料分析與機器學習」，但整門課的主軸是機器學習（含深度學習），資料分析是為它服務的。

### 課程平台與上課方式

- **E3 教學平台**：講義投影片、範例程式（依章節分開，第一堂課的範例放在「01」）、作業指派與繳交都在 E3 上。投影片會隨進度陸續放上，不會一次全部給。作業由助教批改，成績會即時顯示在系統上（只有自己看得到）；如果助教留言說程式無法執行、沒給分，直接聯絡助教補救即可（助教聯絡方式在課程公告），不用太緊張。
- **課堂錄影**：老師上課時會同步開一個 Google Meet，目的不是讓同學遠端上課（老師希望大家到教室實作），而是方便錄製上課內容——Meet 錄完會直接存進老師的雲端硬碟，之後分享連結給同學做課後複習。
- **教室電腦**：課前已裝好這門課幾乎所有會用到的套件，上課不用重複安裝；但教室電腦有**還原卡**，重開機就會還原成初始狀態，所以課堂上寫的程式碼一定要自己存到雲端、寄給自己或存進 USB，留在電腦裡就找不回來了。
- **自備電腦要裝什麼套件**：老師之後會在 E3 列出清單；更實際的做法是執行範例程式時看到「找不到某套件」的錯誤，就當場安裝那個套件即可。
- **上課節奏**：晚上三節課從 6:30 開始，中間休息一次（老師聽不到下課鈴，會自己抓時間）。

### 課程定位

課程分三塊：**理論**（術語與意義、原理與觀念、經典演算法）、**實作**（資料前處理與模型訓練流程、以 Python 程式實現）、**專題應用**（期末專案）。每堂課的節奏也對應這個分工：前半段講機器學習理論（資料前處理 → 傳統機器學習 → 模型選擇與評估 → 深度學習，難度依序遞增），後半段換成 Python 程式與套件的課堂實作——先介紹該堂課用到的套件的型別與函式，再把前半段學到的理論用程式實現出來。

老師特別強調「實作」指的是**完整的模型訓練流程**：從資料前處理、訓練、評估、超參數調整，一路調到最佳化後決定的模型才拿來用，而不是「套一份資料、隨便一組超參數訓練一個模型」就結束。

「傳統機器學習」是相對於「深度學習」而言：深度學習也是機器學習的一部分，只是特別強調它建立在多層神經網路架構上，而那種架構的訓練需要額外技巧才能讓參數收斂（層數多了之後，隨機梯度更新可能發散或不收斂），所以才另外給它一個名字。老師提醒不要小看傳統機器學習——模型選擇、超參數調整這些核心觀念都是在傳統機器學習裡建立的，前 1–7 週學完就已經有一套完整的機器學習概念，之後只是把當中的模型換成深度神經網路而已。

### 先修科目

- **線性代數**：向量內積、矩陣乘法、矩陣轉置
- **微積分**：函數、微分（含連鎖律）、偏微分、梯度
- **（建議）Python**：型別、資料結構、條件邏輯與流程控制、函式與模組、物件導向程式設計

老師說用到的數學其實不深：線性代數只需要知道內積、矩陣乘法與轉置；微積分主要是在推導梯度時會用到連鎖律，再延伸到偏微分與梯度。課堂上有同學問到「講義裡的微分推導需要自己會算嗎」，老師的回答是不用到會算的程度——講義裡會有推導過程，看不懂某一步怎麼變過去也沒關係，把它當成理所當然接受即可，不必回頭從微積分重學。教材裡如果需要線性代數或微積分的概念，老師會先做簡短補充，學過的同學就當複習。

至於 Python：學過最好；沒學過 Python 但學過其他程式語言也很好，因為條件邏輯、迴圈、迭代、遞迴這些演算法概念在第一次學程式語言時就建立了，換語言頂多是熟悉語法（例如 `if` 後面要加冒號、有些語言的 statement 要加分號）。連程式語言都沒碰過也沒關係——老師的說法是「我們不擅長的事，就請比我們擅長的來做」，也就是請 AI 幫忙寫，但這門課要學的是**怎麼請 AI 寫**（見下一節）。

Python 是多重程式設計典範（multi-paradigm）的語言：可以循序式（sequential）、函式式（functional programming），也支援物件導向（OOP，可以建立類別）。這門課會用到的科學計算套件是所謂「Python 五大科學套件」（NumPy、SciPy、Pandas、Matplotlib、Scikit-learn）再加一個深度學習用的 PyTorch，老師稱之為「5 + 1」。

### 這門課對「程式能力」的要求

老師點出一個時代趨勢：現在大多數程式碼會由 AI 生成，單純「會打字寫程式」的能力（老師戲稱「碼農」——把寫程式比作像農夫一樣逐行敲打維護程式碼）已經不是重點，重點轉向**跨領域、能拆解複雜問題的系統設計能力**：專注在架構設計與問題拆解，剩下的交給 AI。因此這門課對程式能力的要求，不是「會不會寫」，而是**能不能引導 AI 寫出對的程式**——用精確的邏輯、規格與邊界條件下指令，並且有能力檢查 AI 生成的程式碼有沒有邏輯漏洞或安全風險。這個要求會直接體現在後面「AI 協助撰寫 Python 程式」這一節的示範裡。

老師補充了幾個說法來支撐這個立場：現在還在自己一字一字打程式的工程師，生產力一定比不上用 AI 的同事；連老師自己都「寫程式寫不贏 AI，直接投降」——AI 寫出來的架構與語法常常比自己想到的更精簡。「引導」就是用自然語言（中英文都可以，打字或語音都行）跟大型語言模型描述目的、額外要求與限制條件，讓它產生對應的程式碼。但 AI 寫完之後還是要看得懂：老師用「書報總編輯」比喻——小編寫完的稿子，總編輯敢不看就直接出刊嗎？出事是總編輯負責。所以 AI 生成的程式不能不看就執行，至少要看懂邏輯、確認它沒有埋漏洞或扯後腿（雖然現在的 AI 還不至於那麼狡猾，但未來不確定）；執行結果有問題時，看得懂程式才知道可以直接改，或是請 AI 針對那個部分再修改。

為什麼用 Python：它是資料科學領域最受歡迎的語言，語法彈性、屬於高階語言，而且有大量科學計算與機器學習函式庫。老師也坦白講缺點：Python 是直譯式語言，直譯器看到一行執行一行，不像編譯式語言先把整份程式碼讀進去、編譯成機器碼再執行——編譯時能對整體做最佳化（包含記憶體配置），所以效能遠高於逐行直譯。不過套件生態早就考慮到這點：NumPy／SciPy 等函式庫底層是用 Fortran 或 C 實作，對多維陣列做向量化運算而不是用 `for` 迴圈；PyTorch 又能用 GPU 加速。所以在學習與驗證階段用 Python 是最快的方法；真的碰到效能限制時，再考慮把它 transcode 成其他語言重新編譯。

## 本週摘要

### 什麼是機器學習？

傳統寫程式是「人工設計規則」：工程師把邏輯寫死進程式裡（例如「信件包含這幾個關鍵字，就判定為垃圾郵件」）。機器學習反過來——不寫死規則，而是給模型大量資料，讓模型自己從資料裡「歸納」出規律，再把歸納出的規律套用到新資料上。這個「從資料中歸納規律」的過程，就是「學習」。

機器學習模型通常帶有一組「可調參數」，訓練的過程就是不斷調整這些參數，讓模型在訓練資料上的預測誤差越來越小。

老師講定義時的幾個補充：機器學習（以後簡稱 ML，但注意 ML 在其他領域也可能指 maximum likelihood 最大概似）是人工智慧（AI）底下一個非常重要的子領域，沒有機器學習，AI 很多應用目標都達不成。「機器」指的是有計算能力的計算機（computer 翻成「計算機」比「電腦」更貼切），核心概念是**讓計算機透過自我學習的演算法，從訓練資料裡自己找出知識**——訓練資料通常就是能收集到的歷史資料，而「找知識」這件事人不是做不到，只是懶得做，所以交給機器（就像請 AI 寫程式）。學完之後的用途是對沒看過的新資料做出準確的**預測（prediction，也稱 inference）**，包含分類與數值估計——例如根據過去經驗判斷明天股票會不會漲。

以老師舉的**眼底影像多標籤分類**為例：輸入一張眼底影像，模型 f(·) 要同時判斷它符不符合「正常」「糖尿病視網膜病變」「老年黃斑部病變」「青光眼」「白內障」「高血壓性視網膜病變」「病理性近視」「其他」這幾個標籤——一張影像可能同時符合多個標籤，所以是「多標籤」而非單一分類。機器學習要做的事，就是訓練出這個模型 f(·)。

老師對這個例子展開講了幾層：

- **為什麼是眼底影像**：專業眼科醫師從一張眼底攝影就能看出許多病徵——不只眼疾，糖尿病、高血壓這類全身性疾病也會反映在眼底（亮的區塊是視神經、暗的區塊是黃斑部，模糊、混濁、血管不清晰等都是線索）。既然醫師能靠經驗從影像判斷，就有機會訓練一個機器具備同樣的能力；「說穿了就是教機器看圖片」。
- **二分類、多分類、多標籤要分清楚**：二分類是「是／否」「有／無」；多分類有多種類別但**彼此互斥**，是 A 就不會是 B、C、D；多標籤則是一張影像可能**同時**是 A 又是 B（一個人同時有糖尿病、青光眼加白內障完全可能——老師還說現在手機用得兇，年紀輕輕就有青光眼的不少）。做期末專題或論文時，第一件事就是先釐清自己的分類問題是哪一種。
- **多標籤的常見做法**：如果標籤之間沒有互斥關係，一般把每一類各自當成一個獨立的二分類問題，平行跑多個分類器——「有沒有糖尿病視網膜病變」「有沒有老年黃斑部病變」各自判斷，最後合起來就是多標籤的結果。
- **圖片怎麼「丟進」模型**：機器最終只能吃數值。彩色影像會被拆成像素，每個像素有 RGB 三個通道，每個通道用 8 bits 表示 0–255 的數值；例如裁成 224×224 個像素、每個像素 3 個通道，全部都是數字。連跟語言模型對話的文字，最後也是被轉成向量（數值）才進模型。
- **模型不好會怎樣**：正確率不高——實習醫生十個有九個都看得出青光眼，機器卻說正常，這就不行。老師也順帶點出醫療分類的取捨：分類錯誤分「偽陰」與「偽陽」，哪一種比較嚴重因領域而異；在醫學上通常寧可嚴格一點、不要漏掉真正的陽性，頂多多做幾次檢驗確認，也不要讓病人太開心而錯過治療時機。

### 監督式學習：有「標準答案」可以學

當訓練資料同時包含「輸入」與「正確答案（標籤）」時，屬於**監督式學習**——模型的任務是學會「輸入 → 標籤」這個對應關係，訓練完後套用在沒看過答案的新資料上。老師的比喻是給小朋友「題庫加上解答」：有參考解答，他做完才知道哪一題錯了、下次要改進；訓練資料與標籤要**同時**給演算法，訓練出好模型之後，再拿題庫裡沒有的新題目（新資料）來問它。依標籤的型態，又分兩種：

- **分類（Classification）**：標籤是「離散的類別」，例如判斷一張圖片是貓還是狗、判斷一封信是垃圾郵件還是正常信件。模型輸出「屬於哪一類」。
- **迴歸（Regression）**：標籤是「連續的數值」，例如根據坪數、屋齡、地段預測房價、根據氣溫與濕度預測用電量。模型輸出一個數字。

分類跟迴歸的差異關鍵在「標籤的型態」，而不是模型的複雜度——同一種演算法（例如決策樹）稍加改造就能同時做分類跟迴歸。

### 非監督式學習：沒有標準答案，讓資料自己說話

當訓練資料**沒有標籤**時，屬於**非監督式學習**——模型的任務不是學一個對應關係，而是直接從資料本身的結構裡找出規律，或是幫我們推導出標籤。老師用 Iris 資料集舉例：把最後一欄的類別標籤遮起來、只給機器前四欄特徵，看它能不能把資料分成三大群；分出剛好三群代表它學到了規則（它叫不出「山鳶尾」這個名字，但知道這是第 0、1、2 類），只分出兩群代表做得不好，分出四群則是做過頭了。常見兩種任務：

- **聚類（Clustering）**：把相似的資料點自動分成幾個群組，例如依購買行為把顧客分眾、依內容把新聞自動歸類主題。演算法要自己判斷「哪些資料算相似」，沒有人事先告訴它答案。
- **降維（Dimensionality Reduction）**：資料常有很多欄位（維度），但真正有意義的資訊可能只藏在其中幾個「潛在組合」裡。降維把高維度資料壓縮成更精簡的表示，同時盡量保留原本資料裡重要的結構——常用來把資料畫成 2D/3D 圖方便觀察，或替後續模型減少雜訊、加快訓練。

### 半監督學習：兩者之間的折衷

現實中「幫每一筆資料都標好答案」往往很貴（需要人工標註），但「收集大量沒有標籤的資料」通常很便宜。半監督學習拿少量標籤資料加上大量無標籤資料一起訓練，兼顧監督式學習的準確度與非監督式學習的低成本。

### 為什麼這套分類法重要

「監督式 vs 非監督式、分類 vs 迴歸、聚類 vs 降維」是機器學習領域的基本詞彙，因為拿到一個新問題時，第一件事就是先判斷「有沒有標籤」「標籤是類別還是數值」——這會直接決定該挑哪一類演算法、用什麼指標評估好壞：分類常看準確率／precision／recall，迴歸常看均方誤差（MSE）。

### 機器學習的典型任務：預測、降維、分群、生成

把前面談的分類法落到實際任務，機器學習大致做四件事：

- **預測（Prediction）**：分類（Classification，預測離散類別，例如判斷腫瘤良性或惡性）與迴歸（Regression，預測連續數值，例如預測明天氣溫）都屬於預測，差別只在標籤型態。
- **降維（Dimensionality Reduction）**：簡化複雜特徵，例如用特徵提取做資料壓縮。
- **分群 / 集群（Clustering）**：把相似的資料聚在一起，例如電商客群分群。
- **生成（Generation）**：創造出全新且合理的資料，例如文本、圖片與影音多媒體生成——這正是近年生成式 AI（GAI）的核心任務，也是「有無標籤」這套分類法之外，第四種獨立存在的任務型態。

前三種都能套進監督式／非監督式的框架（預測靠監督式學習，降維與分群靠非監督式學習），生成則是另一條路線，通常需要更龐大的資料與模型規模，這也是為什麼機器學習與人工智慧的關係（見後文）要另外拉出來談。老師說這門課會偏重前三種任務，生成比較偏語言模型之後的應用。

老師對這四種任務各補了一些細節：

- **分類的決策邊界**：投影片上紅藍兩群樣本，明眼人一看就知道畫一條線就能分開，但機器要透過數值訓練才能算出這條決策邊界——以後線的右邊判成 B 類、左邊判成 A 類。圖上只有 x₁、x₂ 兩個特徵是為了畫得出來；實際的特徵通常是很高維的長向量，人最多只看得懂三維，維度一高就沒辦法視覺化。如果一個點明明落在 A 區、真實答案卻是 B，那就是異常值（outlier），另當別論。
- **迴歸與誤差**：常見有線性迴歸與非線性迴歸（後者能描述輸入輸出間更複雜的關係）。用一條線去擬合很多 (x, y) 點時，這條線不會通過每一個樣本，只能找一條「大家中間」比較理想的線；給一個新的 x，預測的 y 跟真實值之間的差距就是誤差，做迴歸就是在看這個誤差量有多大。
- **分群的用途**：非監督式的自動分類、探索性資料分析、模式發現——重點是**連人都不知道有幾類**時，請機器幫忙找出關係。
- **降維的兩種用途**：一是資料前處理／壓縮，例如原本 1024 維的特徵最後用 64 個特徵就能取代；二是資料視覺化——投影片上的例子是一個三維的「瑞士卷」（生乳卷）狀分佈，降成二維後看起來清楚得多。要注意降維後的新軸 z₁、z₂ **不會一對一對應**原本的 x₁、x₂、x₃：z₁ 可能是 x₁ 與 x₃ 的某種組合（例如平方和之類），z₂ 則比較接近 x₂，是從資料裡「觀察」出來的。
- **生成要「合理」**：機器隨便也能生成，給它一句話產生一段不搭嘎、沒有文法的輸出也算生成，但沒有意義；我們要的是對人有意義的資料。老師用「畫美人魚」開玩笑——一半人一半魚結果左右分、上下分、加個捲髮就算女的，這些都不是我們要的生成結果。

## 兩種更正式的定義

除了「有沒有標籤」這個實務分類法，機器學習還有兩種常被引用的定義，分別從「效能」與「函式」兩個角度切入：

- **Tom Mitchell 的定義**：一個電腦程式在面對某項任務（Task）時，如果其效能表現（Performance）隨著經驗（Experience）的增長而提升，就說這個程式具備學習能力。
- **李宏毅的定義**：讓機器具備「找一個函式（Function）」的能力——透過訓練資料，讓電腦自動尋找能解決特定問題的未知函式（帶有未知參數的函式，稱為參數化模型）。

這剛好呼應前面提到的「可調參數」：訓練的本質就是在調整模型（一個帶未知參數的函式）裡的參數，讓它在訓練資料上的預測誤差越來越小，也就是 Mitchell 定義裡「效能隨經驗提升」的具體做法。

老師的解讀：Mitchell 的定義偏數學化，一般人不好懂，白話就是「給它越多資料它做得越好，就是有在學習；否則就是停滯不前」。李宏毅的「找一個函式」則是一般人最能接受的說法。這裡的函式就是一個規則：給一個輸入 x 就吐出一個輸出 f(x)（習慣寫 f 只是因為 function 開頭是 f，寫 g(x)、h(x) 都可以）；不同的 x 可以對應到同一個輸出（多對一可以），但**一個 x 不能出來兩個不同的結果**。老師再拿股票舉例：如果能找到一個很厲害的函式，輸入過去的歷史資料（今天以前的 K 線、川普講了什麼話……）就能預測明天漲跌，那這個函式就值錢了；函式裡跟這些輸入相關的參數要長什麼樣，就得靠歷史資料去訓練它——這就是「參數化模型」。模型好，預測的準確率就高。

## 核心術語一次搞懂

初學機器學習常卡在術語上，這裡把老師在第一堂課列出的「常見（易混淆）術語」全部定義一次；其中有些要等到對應週次才會實際動手操作（梯度下降、反向傳播、正則化等），先在這裡建立定義，之後會用程式範例把它們串起來。

老師為什麼要在第一堂課就把術語攤開來講：機器學習領域的術語非常多、很多又很相近，不釐清的話，之後跟別人溝通或看論文會誤解對方的意思；而且**懂術語才知道學習效果不如預期時該「用哪一招」**——老師的比喻是數學不好就補數學、國文不好就補國文，不會因為國文考不好而拼命看數學；同理，發現模型 overfitting 就要用正則化去限制它，每個術語背後都對應一種對症下藥的手段。用錯術語也會很丟臉：明明畫的是 loss curve，論文裡卻寫成 learning curve，人家會覺得「這都不懂還做這方面的研究」。

### 模型與資料的基本組成

- **Model（模型）**：機器學習的核心實體，一個數學公式或演算法結構，負責學習資料中的規律——也就是訓練要找出來的那個函式。
- **Sample（樣本）**：資料集中的一筆觀測紀錄，對應表格的一橫列。
- **Feature（特徵）**：描述樣本的屬性或維度，對應表格的一直欄，也稱輸入或變數。
- **Target / Label / Ground truth（目標／標籤／真實答案）**：模型要預測的答案。Label 通常指資料集裡附帶的標籤，Ground truth 則強調它是「真實」答案。

老師補充：一筆樣本通常做不了什麼事，要有一組大量的樣本才觀察得出規則。用函式的語言來說，特徵是輸入、自變數（independent variable），目標是輸出、應變數（dependent variable）——根據 x 的值會得到不同的 f(x)。另外，機器學習是很多領域匯流而成的，各領域會把自己的名詞帶進來，所以同一個東西有很多叫法（見後面 Iris 一節的同義詞整理）。

標籤怎麼來也很關鍵：**標註需要領域知識**。採集鳶尾花的人如果自己都分不出品種、用猜的填標籤，機器就不可能答對；標註樂器音高需要懂音樂的人；眼底影像的標註只能拜託眼科醫師，或是從過去的病歷（影像 + 醫師的診斷證明）對應建立起來，一般人做不到。所以做監督式學習時，標註是資料集裡最辛苦、也最關鍵的一環，大部分還是靠人工——老師打趣說「如果機器能幫你標註，那你還需要再訓練另一個機器來預測嗎？」，除非你要做一個比它更厲害的。簡單的任務（貓狗分類）可以請工讀生標；很多領域也有別人標好的公開資料集可用，例如影像領域有 1000 類生活圖片的資料集，眼底攝影也有公開資料集。

### 特徵前處理

- **Feature scaling（特徵縮放）**：訓練前把不同量級的特徵拉到同一個尺度，讓每個特徵公平參與計算，避免數值範圍大的特徵主導模型。
  - **Normalization（正規化）**：把特徵線性縮放到固定範圍（通常是 [0, 1]），公式為 `(x - min) / (max - min)`；缺點是對離群值（outlier）敏感，一個極端值就會壓縮其他資料的分布範圍。
  - **Standardization（標準化）**：把特徵轉換成平均值 0、標準差 1 的分布，公式為 `(x - mean) / std`（也稱 z-score normalization）；不設固定上下限，對離群值較穩健，是深度學習與多數線性模型更常用的做法。
- **Feature selection（特徵選取）v.s. Feature extraction（特徵提取）**：選取是從原始特徵中挑出有用的子集（欄位不變，只是刪減）；提取則是把原始特徵組合、轉換成新的、更精簡的特徵（例如 PCA 降維），欄位本身已經改變。

老師對這幾個名詞的補充：

- **Normalization 與 Standardization 連碩士生都不一定分得清**，中文特意翻成「正規化」與「標準化」兩個不同的詞就是為了區隔；做 feature scaling 時要看特徵的特性選其中一種策略。有人甚至會把它們跟 **regularization（正則化）** 搞混——那就太誇張了，因為正則化根本不是在做特徵縮放，而是在約束可學習參數的權重不要太大，避免 overfitting；前兩者搞混還說得過去（確實有點像），跟正則化搞混則是屬性完全不同。
- **為什麼特徵工程很關鍵**：有些特徵只是「煙霧彈」，對機器學習知識沒有幫助，反而是雜訊會讓它學不好。老師的比喻：明天要考國文，前一晚卻拼命做英文複習考和數學模擬考，腦袋裝了一堆不相關的東西、試圖從裡面整理出邏輯，結果一定考不好。
- **選取 vs 提取用「3 變 2」記**：三個特徵變兩個，選取是直接從三個裡挑兩個、另一個丟掉；提取則是三個「融合」成兩個新特徵，三個的特色都被融進去了。
- **CNN 的本質就是特徵提取**：把一張密密麻麻全是像素的圖片，最後變成一個向量——看穿了，卷積神經網路做的就是 feature extraction。

### 訓練流程的基本節奏

- **Trainable parameters（可訓練參數，含 weights 權重與 bias unit 偏差項）v.s. Hyperparameters（超參數）**：前者是模型在訓練過程中自動從資料學出來的參數；後者是訓練開始前由人手動設定、用來微調模型表現的參數（例如學習率、樹的深度、batch size）——調校模型時真正能「手動控制」的只有超參數。
- **Training（訓練，亦稱 Model fitting）**：用訓練資料反覆調整可訓練參數，讓模型在訓練資料上的預測誤差變小的過程。
- **Epoch**：訓練過程中把整份訓練資料完整跑過一輪，稱為一個 epoch；模型通常需要跑過多個 epoch 才會收斂。
- **Validation（驗證）**：用另一批不參與訓練的資料，檢查目前模型或超參數設定的表現，作為調整依據。
- **Testing（測試）**：訓練與調整都定案後，最後拿一份從頭到尾都沒被用過的資料，評估模型對「全新資料」的最終預測能力。三者（Training／Validation／Testing）不可混用。

老師對超參數與 epoch 的補充：

- **調超參數不是擲骰子**：初學者常覺得訓練像在下賭注——今天靈機一動調一組參數，結果不錯就開心得要死，然後每天祈禱下一組會更好。其實不是這樣：有系統化的做法，用某種程度的「暴力解」把你有興趣的超參數範圍全部跑一遍（例如 grid search），只要算力夠，就沒有運氣的問題。
- **學習率是超參數的典型例子**：梯度下降每次要往前走幾步，是人告訴機器的，不是機器學來的；即使做成適應性調整（例如第幾個 epoch 之後降到多少），規則仍然是人設計的。
- **為什麼同一份資料要看很多輪**：學習演算法（隨機梯度、mini-batch 梯度）不是一次看完整包資料就算出標準答案，而是跌跌撞撞每次走一小步；整份資料看完一輪之後，下一輪從不同的出發點再看同樣的資料，會有新的見解、再往前進步。
- **Epoch 數本身也是超參數，不是越多越好**：參數量大的模型把同一套訓練資料看太多次會「拿翹」，開始 overfitting，參數調整的方向就走歪了。訓練要看幾輪，到時候會是一個重點。

### 梯度下降家族

- **Loss function（損失函數）**：衡量模型預測值與 ground truth 之間差距的函數，數值越小代表預測越準；訓練的目標就是調整可訓練參數，讓 loss function 在訓練資料上最小化（迴歸常用均方誤差 MSE，分類常用 cross-entropy）。
- **Activation function（激活函數）**：神經網路中每個神經元完成線性加權運算後套用的一個非線性函數（例如 sigmoid、ReLU、tanh），作用是讓網路能表達非線性關係——沒有它，再多層的網路疊起來仍等價於一層線性運算。
- **Gradient descent（梯度下降，亦稱 Full-batch / Batch gradient descent）v.s. Stochastic gradient descent（SGD，隨機梯度下降）**：梯度下降每次更新參數前，用「全部」訓練樣本計算 loss 的梯度再往反方向調整，方向穩定但資料量大時計算成本高；SGD 每次只用「一筆」隨機抽樣的樣本就更新參數，更新快、有機會跳出局部最低點，但方向震盪較大。
- **Mini-batch v.s. Full-batch**：兩者的折衷——mini-batch 每次用一小批樣本（例如 32、64、128 筆）計算梯度後更新，兼顧計算效率與穩定性，是深度學習最常用的方式；full-batch 就是前面說的梯度下降，用全部樣本。
- **Backpropagation（反向傳播）**：訓練神經網路時，用連鎖律（chain rule）從輸出層往輸入層反向、逐層計算 loss 對每個參數的梯度的演算法，是梯度下降能有效率套用在多層網路上的關鍵技術。

老師的一句話版本：「機器學習的目標就是選一個適合的損失函數，然後讓它越小越好——一句話講完就是這樣，但過程很辛苦。」為什麼要靠梯度下降：因為通常**沒有 closed-form solution**（沒辦法一步算出最小值），只能仰賴這種迭代式的更新，每次往目標走一小步、更新一點點，持續往目標邁進。Activation function 的「啟用」翻譯有點奇怪，老師的解釋是：根據輸入經過這個函數之後可能出現不同的數值，有時是線性、有時是非線性，所以叫「啟用」。

### 模型選擇、驗證與評估

- **Model selection（模型選擇）**：在多個候選演算法或超參數組合之間，挑出表現最好的那一個。
- **Model validation（模型驗證）**：用驗證集評估模型在「沒訓練過的資料」上的表現，作為 model selection 的依據，避免只憑訓練集的表現做決策。
- **Model evaluation（模型評估）**：用適當的指標（accuracy、precision、recall、F1-Score、MSE 等）衡量模型好壞，通常在最後的測試階段進行，得出模型的最終評估結果。

### 診斷曲線

- **Loss curve（損失曲線）**：橫軸是訓練迭代次數（iteration / epoch），縱軸是 loss 值，用來看模型有沒有正確收斂（loss 應持續下降）。
- **Learning curve（學習曲線）**：橫軸是訓練樣本數量，縱軸是模型在訓練集／驗證集上的表現，用來診斷模型是否需要更多資料，或有 high bias／high variance 的問題。
- **Validation curve（驗證曲線）**：橫軸是某個超參數的數值（例如樹的深度、正則化強度），縱軸是訓練集／驗證集的表現，用來找出該超參數的最佳設定值，是 model selection 常用的診斷工具。

### 過擬合與正則化

- **Overfitting（過擬合，high variance）**：模型過度擬合訓練資料裡的細節與雜訊，在訓練集表現很好、但在驗證／測試集表現明顯變差——模型「記住」了訓練資料，而不是學到通則。
- **Underfitting（欠擬合，high bias）**：模型太簡單，連訓練資料本身的規律都學不好，訓練集與驗證集的表現都不理想。
- **Regularization（正則化）**：在 loss function 中加入一個懲罰項，限制可訓練參數（權重）不要過大，藉此抑制模型複雜度、緩解 overfitting，常見作法有 L1、L2 正則化。
- **Dropout（失活）**：訓練神經網路時，每次迭代隨機「關閉」（失活）一部分神經元（不參與這次的前向與反向傳播），迫使網路不能過度依賴少數幾個神經元，是深度學習裡常見的 overfitting 對抗手法。

老師用「聰明的小朋友背題庫」把 overfitting 與 underfitting 講得很具體：

- **Overfitting**：一個很聰明的小朋友，你給他複習考的題目，他把題目全部背下來，明天考同樣的題目就拿 100 分；但只要考的不是那些題目，表現就變得很隨機，突然掉到五六十分。原因是他把聰明用錯地方——參數量夠大，發現只要把參數調成某個樣子就能把訓練資料每一題完全答對，於是「背」下訓練資料而不是學規則。這就是 high variance；碰到沒看過的資料就沒轍。
- **Underfitting**：腦容量不夠大，題目背不起來、規則也抓不到，什麼都不行——這是一定要避免的（high bias，本身就有偏差）。如果模型自由度不夠高，或根本沒辦法描述非線性的問題，怎麼調都沒用。
- **所以設計上的策略是**：模型傾向於讓 capacity 大一點（小朋友比較聰明），再用約束手段（正則化、dropout）叫他「不要硬背題目，去學題目裡的規則」。這遠比要一個什麼都不懂的小朋友答對題目容易。
- **Dropout 為什麼有效**：神經元全部連得好好的時候自由度很大，很容易硬背答案；訓練時故意讓某些神經元「要通不通」，網路就發現「怎麼那麼可怕」，必須善用剩下的神經元、建立冗餘的路徑來容錯（你關掉這個我還是答得對，關掉那個我也可以），等於把它的能力在訓練中「腰斬」，逼它用剩下的去習得規則。驗證與測試時神經元全部開啟，「封印解開」，結果反而更好。老師說這是一個很神奇的技術，之後講深度學習會用到，因為深度學習其實並不好訓練——這也是它特別叫「深度」學習的原因：層數多了，隨機梯度更新可能發散或不收斂，需要額外的技巧來對付。

## 資料長什麼樣子——以 Iris 資料集為例

判斷一份資料能用什麼方法處理，通常從三個角度分類：

| 判斷角度 | 分類 | 範例 |
| --- | --- | --- |
| 有無結構 | 結構化（Structured） | 二維表格資料、關聯式資料庫 |
| | 非結構化（Unstructured） | 自由文字、圖片、影音 |
| | 半結構化（Semi-Structured） | JSON、XML、HTML 檔案（靠標籤或 key-value pair 表達階層） |
| 有無標籤 | 有標籤（Labeled） | 照片＋標籤「這是貓」 |
| | 無標籤（Unlabeled） | 手機相簿匯出的旅遊照片、網頁伺服器造訪軌跡 |
| 數學特性 | 數值型・連續（Continuous） | 身高、房價、氣溫 |
| | 數值型・離散（Discrete） | 房間數、員工人數 |
| | 類別型・名義（Nominal，無順序） | 性別、血型、顏色 |
| | 類別型・順序（Ordinal，有順序） | 學歷「學士／碩士／博士」、滿意度「低／中／高」、尺寸「S／M／L」 |

老師講這張表時特別強調兩件事。第一，這三個角度是要讓同學聯想到自己的期末專題與研究資料：**你的資料到底有沒有結構、有沒有標籤、是什麼數學型態？**第二，**類別型特徵一定要先轉成數值才能進機器計算**，而這裡有個陷阱：把性別編成 male = 0、female = 1 看起來很自然，但對電腦而言 1 就是比 0 大，等於暗示男生「數值上比較大」，這不好。名義型類別要用**獨熱編碼（one-hot encoding）**：用一組 0/1 表示，只有屬於的那一類是 1、其他都是 0（例如 `01`／`10`），電腦就不會產生誰大於誰的概念；類別再多也一樣，博士就在博士那格勾 1、其他都是 0。反過來，**順序型類別（學士／碩士／博士）本來就有大小關係，反而應該讓數值反映出來**，不能跟名義型混在一起處理。這些會在資料前處理那一週詳細講。

老師也用「資料集」開場強調：**一切都來自資料集，沒有資料集就沒有機器學習**——機器要從資料裡學習、轉化成知識，你收集不到資料，後半段就不存在；而資料的品質決定了機器學習最後能做到多好。

機器學習領域的經典入門資料集 **Iris（鳶尾花）** 剛好是這三個分類的教科書範例：150 筆觀測、每筆是結構化的一橫列，4 個連續數值型特徵（花萼長寬、花瓣長寬，單位 cm），加上 1 個名義型類別標籤（Setosa / Versicolor / Virginica 三種鳶尾花），且資料乾淨、沒有缺失值，所以常被拿來當分類與分群演算法的基準測試。

老師對 Iris 的補充：

- **麻雀雖小、五臟俱全**：150 筆算很少，但它注意到了資料的平衡性等細節，是很標準的基本測試用資料集，Scikit-learn 內建。
- **每類 50 筆是「均衡」的**——現實中收集到的樣本很少每一類都均衡，有些類別本來就很少（例如少數、稀有疾病），樣本很難收集，這會造成機器學習的困難：你希望它認得少數疾病，但那類資料又非常少。
- **沒有缺失值也是難得的**：缺失值（missing value）非常常見——工讀生沒記到、塗改看不清楚、問卷某題沒回答。處理方式最簡單是整列丟掉，但如果缺失很多會把大部分樣本都抽掉，所以常會**補值**，例如用同一個特徵的平均值補，或用鄰近樣本的值補；後面會專門討論。
- **資料是按類別連續排列的**：第 1–50 筆是同一類、51–100 第二類、101–150 第三類，沒有打散；訓練時自己 shuffle 即可。（老師順帶指出投影片上「第 50 筆開始是第二類」寫錯了，應該是第 51 筆。）
- **花瓣與花萼要分清楚**：花瓣（petal）是中間小小的那一片，往下垂的大片是花萼（sepal），各量長與寬。Setosa（山鳶尾）的特色是花瓣特別迷你，它的花瓣長寬兩個數值遠小於 Versicolor 與 Virginica。
- **分類與分群都能用它**：分類需要標籤；分群則把標籤欄遮起來不用，看演算法能不能自己把資料拆成三大類。
- **鳶尾花實際上的品種應該不只三種**，這個資料集只收集了三種。

由於機器學習是很多領域匯流而成，同一個東西有很多叫法，老師整理如下：

| 概念 | 常見同義詞 |
| --- | --- |
| Feature（特徵） | input（輸入）、attribute（屬性）、measurement（量測值）、dimension（維度，較少見）、independent variable（自變數） |
| Sample（樣本） | instance（實例）、observation（觀測） |
| Target（目標） | label（標籤）、class label（類別標記，分類問題最常用）、output（輸出）、ground truth（真實答案）、dependent variable（應變數） |

## 強化式學習——第三種學習方式

前面談的監督式／非監督式學習都是從「靜態資料」裡學規律，但還有一種**強化式學習（Reinforcement Learning, RL）**：代理人（Agent）透過與環境（Environment）互動、採取行動（Action）、試錯（trial-and-error），並根據獲得的獎勵（Reward）去學習一套能讓總獎勵最大化的策略。

RL 跟監督式學習的關鍵差異在於「回饋的型態」：監督式學習有明確的正確標籤可以直接比對誤差；RL 沒有標準答案，只有一個衡量「這個行動好不好」的獎勵函數，而且獎勵有時是延遲的（做了一連串動作後才知道好壞），例如 AlphaGo 下圍棋要等一整盤棋下完才知道輸贏。

老師的說法是：如果硬要歸類，強化式學習**比較偏向監督式學習**，因為畢竟有一個獎勵函數在提示「這個決策做得對不對」——只是這個回饋不是正確的真實標籤或數值，而是衡量行動表現的分數。做得好給正面獎勵，做得不好給負面獎勵（像懲罰），它從錯誤中學教訓，有點像人的學習方式：以後盡量往被鼓勵的方向做、避免犯被懲罰的錯。

兩個例子：

- **自駕車**：代理人透過感應器與視覺影像輸入，假設只看「方向盤要轉幾度」這一個決策——前方有障礙物時，大轉方向盤會打滑失控（結果不好），稍微偏轉就能繞過（結果好）；它從試錯中學到「要閃躲，但角度不要超過多少」。
- **AlphaGo**：狀態是棋盤上所有棋子的位置，輪到它下時要決定落在哪個新位置。下得好不好不是當下就能知道，要到棋局結束才有結果，所以是**延遲回饋**：最後贏了代表這一路的策略不錯，輸了代表行不通，反覆訓練後得到好的棋路規則。老師也提到當年 AlphaGo 沒有機械手臂，要靠一個人根據它算出的位置幫忙落子——那個人等於只是背後下指導棋的「棋靈王」。

三種學習方式的比較：

| | 監督式學習 | 非監督式學習 | 強化式學習 |
| --- | --- | --- | --- |

## 建立機器學習系統的工作流程

以監督式學習的預測建模為例，建立一套機器學習系統不是「選一個演算法訓練完就結束」，而是一個會反覆調整的迴圈：

1. **選擇特徵並收集帶標籤的訓練樣本**
2. **選擇效能指標**——例如正確率（Accuracy）、精準率（Precision）、召回率（Recall）、F1-Score
3. **選擇機器學習演算法並訓練模型**——通常先由這一步切入，之後再回頭處理其他議題
4. **評估模型的效能**——從訓練樣本中抽出一部分作為驗證集（不參與訓練），拿來評估表現
5. **調整演算法設定並優化模型（或更換演算法）**——也就是調整超參數

這五步不是線性跑一次就結束：第 4 步評估完若表現不理想，會回到第 5 步調整超參數、甚至回到第 3 步換一個演算法，形成一個迴圈。老師說這門課會先從第 3 步「訓練模型」切入，讓同學先對「機器是怎麼被訓練的」有感覺，之後在過程中自然會遭遇特徵提取、指標選擇（是看 MSE 還是準確率）、效能評估等問題，再一一回頭處理。

**什麼時候該換演算法**：如果超參數怎麼調都只在某個上下限之間跑來跑去、沒辦法大幅改善，代表模型本身不合適——例如模型太過簡單，怎麼調都是 underfitting，那就直接砍掉重練換一個新架構，選一個稍微複雜一點的、再盡量不讓它產生嚴重 overfitting，效果會比較好。

背後的原因是機器學習領域公認的 **No Free Lunch 定理**：不存在一個分類器能在所有可能的場景下都表現最好。因此正確的做法是**至少比較幾種不同的機器學習演算法**，才能替手上這個具體問題挑出最適合的模型——這也是為什麼「選擇機器學習演算法並訓練模型」在流程裡通常不會只做一次。老師的講法是：為什麼不能訓練一個分類器又會分貓狗、又會看眼底攝影、又會預測股票？坦白說就是沒辦法——會分貓狗不代表會分白內障跟青光眼。你當然可以硬做一個兩者都會的，但通常不會比拆成兩個分類器各自做來得好，就像要求一個學生國英數理化全方位都強比較辛苦，只培養他最有興趣的數學則容易得多。另外比較模型時也要留意公平性：通常是在**參數量差不多的模型之間**挑最好的；模型複雜度差太多本來就不公平，複雜的模型天生條件就比較好。「最好」的定義則是：以你選定的評估指標，在驗證集上得到的結果最理想。

教科書上這張工作流程圖（S. Raschka, *Machine Learning with PyTorch and Scikit-Learn*）把上面五步拆得更細，補了幾個容易被忽略的細節：

- **測試集從一開始就切開，全程不能碰**：原始資料先切成訓練集與測試集，測試集要留到「最終模型」出爐後才拿出來做最後一次評估；訓練與調參全程都不能用到它，否則等於讓模型「偷看」了未來要考的題目。
- **前處理其實是兩條各自獨立的管線**：一條（缺值處理、初步特徵擷取／選取）套用在整份原始資料上；另一條（特徵縮放、降維）只套用在切出來的訓練集上，處理完才拿去訓練——這樣切分是為了避免測試集的統計資訊（例如平均值、標準差）提早滲進訓練流程。
- **調參迴圈其實是靠交叉驗證跑的**：「選超參數 → 訓練 → 評估」這個迴圈明確靠交叉驗證（cross-validation）反覆執行，跑到選出候選模型為止，才進入最終訓練得到最終模型。
- **最終模型上線時，前處理要原封不動帶著走**：套用到全新資料做預測前，得先用同一套前處理管線處理過，模型與前處理是綁在一起交付的，不能只帶模型、忘記帶前處理設定。

老師說這一頁非常重要，之後講模型選擇與評估時還會再回來看，並沿著圖逐段解釋：

- **Raw data 這一段**：資料可能是自己收集的，也可能是別人建好的資料集（那通常可以直接跳到下一步）。自己收集時第一關就要篩選——例如問卷調查會故意放一些前後矛盾的題目，抓出無腦作答的人（一下說好一下說不好、或全勾 5 分／1 分），那種直接丟掉。接著處理缺失值：某個欄位沒記錄到，這筆樣本還要不要？要的話該補什麼值？程式語言常常預設沒填就是 0，但這不一定對。還有從人的角度做初步的特徵篩選：跟問題明顯無關的特徵（例如「今天的濕度」對股市漲跌）就先丟掉，不要造成機器的困擾。這些初步的特徵擷取／選取大多是靠人、靠專家的看法決定的，還不是機器在做——我們講的機器學習，通常是指**資料集成形之後**的事。
- **雙黃線**：拿到資料集後不急，第一個最重要的原則是**先切成訓練用與測試用兩塊**。測試集切出來之後就「冰起來、找個洞埋起來」，直到模型訓練好才解封做最後評估；挑選模型的階段完全不能看它，看了就失去客觀。老師在圖上畫了一條雙黃線，「跨越就科技執法拍照」——線之後的測試集跟你無關，還沒到那個程度。
- **那怎麼知道做得好不好？暗扛一部分題庫當模擬考**：從訓練集裡偷偷再切一小部分當驗證集，其餘才真正拿來訓練。這不算犯法——沒有去拿真正的期末考題，只是拿自己藏起來的一小塊當複習考。也可以做交叉驗證，在訓練集裡輪流抽一部分當驗證集，不會永遠都是同一批資料在驗證。驗證結果不錯就比較有信心，再換另一個模型看會不會更好；做幾輪之後發現某個模型加某組超參數最好，就決定是它——「小火龍就是你了，明天上戰場」，終於可以去跟測試集 PK。
- **為什麼要做特徵縮放**：有的特徵動態範圍很大（甚至負無窮到正無窮），有的只在 ±1 之間變化，這兩個特徵是不對等的。沒有縮放的話，機器算誤差時全被範圍大的特徵主導（dominate），那個 ±1 的特徵就算很關鍵、勝負就差在它，誤差上也抵不過大範圍造成的誤差，等於被忽略掉。老師的比喻：明明這個人講話比較可靠，但另一個人講話比較大聲，就聽大聲的——我們要看的是說話品質而不是音量，所以要把特徵範圍調整到相似的大小。
- **模型擬合（model fitting）在做什麼**：模型架構是我們先定好的，但當中很多參數是未知的，一開始只是隨機初始化塞進去，絕對不是最佳（不可能一下就命中每個參數），要靠大量資料把它們調成最佳參數。
- **訓練為什麼很花時間**：同一個模型、同一組超參數，這麼多筆樣本要看好幾輪（epoch）；接著同一個模型還要換另一組超參數再看一遍；接著連模型都換掉再重複一次。經過這麼多輪 PK，最後才選出「這個模型搭配這組超參數」是最好的選擇。整個過程是一個很大的迴圈，靠迭代加驗證（交叉驗證）進行，最後從一大堆候選模型中選出勝出者做最終訓練。
- **測試集的結果就是未來上線的預估**：因為那些都是模型沒看過的資料，只要未來真實資料跟測試資料的分佈相似，結果就會相似。跟主管報告「預估正確率大概 97%」時，一定要用測試集上跑出來的數字——訓練集或驗證集的結果不準，因為模型反覆看過答案好多次。如果上線後資料分佈跟當初收集的差很多，那要檢討的不是模型，而是**一開始的資料收集**為什麼跟實際上線的情況不一樣，那是一開始就做錯了。

## 機器學習與人工智慧的關係

人工智慧（AI）是一個終極目標，因為目標太遠大，實際上會分階段逐步邁進；機器學習（ML）則是達成這個目標的其中一種**手段**——ML 把資料轉換成知識，深度學習（Deep Learning, DL）又是 ML 底下特別強大的一種手段。

| AI 階段 | 代表技術／概念 | 核心能力 |
| --- | --- | --- |
| 當前階段 | GAI（生成式 AI） | 內容的創造與文字／影像生成 |
| 現在～近未來 | AI Agent（代理人） | 自主規劃步驟、使用工具完成線上任務 |
| 下一階段（躍升） | Physical AI（具身智能） | 結合硬體與機器人，在物理世界採取行動 |
| 終極目標 | AGI／ASI（通用／超級 AI） | 跨領域自學、自我反思，達到或超越人類智慧 |

AGI（Artificial General Intelligence，通用人工智慧）與 ASI（Artificial Superintelligence，超級人工智慧）是這條演進路線的終點；目前普遍認為正處在「生成式 AI 邁向 AI 代理人」的階段。這張分期表也解釋了這門課的位置：機器學習是整條路線最基礎、最核心的手段，不管未來走到哪個階段，都是建立在這門課教的觀念與方法上。

老師的補充：

- **AI 是人類的終極目標**（老師說「我不知道除了人工智慧之外未來還有什麼」），目標太遠大所以要分階段前進——把大問題拆小是常見的解題手法。生成式 AI 之前其實還有一個階段：**鑑別式 AI**，針對具體問題做簡單的分類與預測，例如協助眼科醫師做眼底攝影分類，這就很有價值了——醫師不再是一個人做決策，有機器輔助，責任不那麼大，也比較輕鬆。
- **AI 代理**：不是單一指定動作結束，而是自主規劃一連串動作、使用工具完成線上任務，甚至可以產生 skill 讓它重複使用。
- **Physical AI**：中文翻成「具身智慧」比較文言，說穿了就是機器人——不限人形，機器狗跳來跳去的也是，有一般生活用途也有軍事用途（老師說重點是機器狗身上還背了機槍），在物理世界採取行動。
- **AGI／ASI**：跨領域自學、自我反思，這連人類自己都還在追求；機器有了這種智慧就跟人類一樣或超越人類。
- **ML 與 DL 的集合關係**：AI 是最大的範圍，當中有一些問題透過 ML 技術完成（ML 把資料轉成知識、實現特定任務、達成階段目標），ML 當中又有一套特別厲害的技術叫 DL——現在比較厲害的模型幾乎都是深度神經網路。但老師強調：**不是所有分類問題都一定要用深度神經網路解**，依資料情況，有些問題不用深度學習就能做得很好。

## Python 環境建置

這堂課後半段開始進入實作，第一步是把 Python 開發環境建起來。

老師在課堂上因為時間關係只示範到「在 VS Code 選擇 Python 直譯器」這一步（下面「建置步驟」的第 2 點），安裝外部函式庫之後的內容留到下一堂再說明；回家作業是**自己在電腦上照講義做到第 50 頁**——能寫出並執行一行 `print("Hello, World!")`，就代表開發環境可以運作。下週會直接從「請 AI 幫我們寫程式」開始講。做到第 50 頁之前有問題可以 email 老師。教室電腦已經裝好環境，不用重做這些步驟；想在自己電腦上用才需要。

### 開發環境的組成

- **Python 主程式**：包含直譯器（Interpreter，`python.exe`）、套件管理工具 `pip`、以及內建的標準函式庫
- **IDE（整合式開發環境）**：課程推薦輕量且強大的 **Visual Studio Code**，負責程式碼編輯、編譯／直譯、連結、執行、除錯
- **外部函式庫（第三方套件）**：NumPy、SciPy、Pandas、Matplotlib、Scikit-learn、PyTorch 等
- **（選用）虛擬環境（Virtual Environment）**：為不同專案建立獨立的套件庫，避免版本衝突

老師對這幾個組成的說明：Python 主程式本身只有直譯器加套件管理工具，「就像要編輯 Word 內容得先開 Word」，還需要一個能編輯、執行、畫圖的工作環境，也就是 IDE。IDE 有很多種可以互相替代，老師個人推薦 VS Code，因為它是**通用型**的整合式開發環境——喜歡它的介面的話，未來開發其他程式語言也能用同一套。虛擬環境之所以列為選用：專案開發常跟當初使用的套件版本綁在一起，套件版本一改程式碼可能就要跟著動，所以正規做法是每個專案建立各自的環境；但課堂學習用途應該還好，因此列為 optional。

Python 之所以在資料科學圈這麼流行，除了語法親和，關鍵是**大量科學計算與機器學習函式庫**：NumPy／SciPy 做科學計算、Pandas／Matplotlib 做資料分析與視覺化、Scikit-learn／PyTorch 做機器學習與深度學習。缺點是直譯式語言效能不如低階語言，但 NumPy／SciPy 底層建立在 Fortran 與 C 之上、能做快速向量化運算，PyTorch 又能透過 GPU 有效率訓練深度神經網路，某種程度彌補了這個劣勢。

### 建置步驟

1. **安裝 Python 主程式**：從 Python 官網下載安裝檔（依作業系統選擇），安裝時務必在視窗底部**勾選「Add python.exe to PATH」**，再點擊「Install Now」。裝完打開終端機輸入 `python --version`，能正確顯示版本號（例如 `Python 3.14.6`）就代表成功。
   - 老師建議下載官網的 **install manager（安裝管理員）**，它會把相關細節都整理好，不要用傳統的 standalone 安裝檔。
   - Windows 直接在下載頁按下載即可；**Mac 要先確認自己的 CPU 架構**——近幾年買的蘋果電腦都是 Apple Silicon（M1／M2／M3 這類 ARM 架構），更早期的是 Intel（x86），下載時要選對。
   - 「Add python.exe to PATH」的意思是把 Python 加進作業系統的環境變數，之後在任何目錄下都能直接執行 `python` 指令，不用跳到放 `python.exe` 的實體路徑。後續步驟基本上「下一步、下一步」一鍵到底。
   - 版本號不必跟講義一模一樣：`3.14.6` 只是老師做講義當時的版本，裝到 `3.14.7` 代表你裝的更新，子版本差一點沒關係；Windows 用「命令提示字元」、Mac 用「終端機（Terminal）」查看。
2. **安裝 VS Code**：從官網下載對應作業系統與處理器架構（x64／Arm64／…）的安裝檔，直接執行安裝。裝好後在「擴充功能（Extensions）」搜尋 Python，安裝微軟開發的三個套件：**Python**（官方核心套件）、**Pylance**（語法補全與靜態型別檢查）、**Python Debugger**（中斷點、變數監控、逐行除錯），以及獨立出來的 **Python Environments**（虛擬環境管理）。裝完記得重啟 VS Code。接著用 `Ctrl+Shift+P` 開命令面板，搜尋「Python: Select Interpreter」選擇剛才安裝的 Python 版本。
   - Windows 選 **User Installer**；Linux 要看套裝版本屬於 Debian 系（Ubuntu 用 `.deb`）還是 RPM 系（SUSE、Red Hat 用 `.rpm`），兩大陣營安裝方式不同；Mac 分 Intel chip 與 Apple Silicon 兩種下載，另有一個 Universal 版，老師說不確定它靠不靠譜，他自己會照實際 CPU 架構挑對應版本。
   - 安裝時可在「選擇附加工作」勾選「建立桌面圖示」方便快速啟動，其他維持預設。
   - 為什麼要裝 Python 擴充功能：VS Code 是通用型 IDE，裡面可以裝 Python 直譯器、也可以裝 C++ 編譯器，需要透過擴充模組才能把「VS Code」跟「剛安裝的 Python 主程式」關聯起來。擴充功能頁面若顯示「Install」代表還沒裝，顯示齒輪或已在「Installed」清單就是裝好了。
   - 「Select Interpreter」這步很重要：同一台電腦可以裝多個版本的直譯器，這一步是告訴 VS Code 執行 `python` 指令時要用哪一個，選剛才安裝的那個版本即可。
3. **安裝外部函式庫**：在 VS Code 下方 Panel 開啟 TERMINAL 頁籤，執行：

   ```bash
   python -m pip install -U numpy matplotlib seaborn scipy pandas scikit-learn torch torchvision
   ```

   等 pip 依套件相依性下載安裝完成即可。老師說這一步只要把這行指令貼到 VS Code 的 TERMINAL 按 Enter，它就會跑一連串下載，把套件直接裝進去。

### AI 協助撰寫 Python 程式

（這一節與下一節「載入 Iris Dataset」是講義第 50 頁之後的內容，第一堂課因時間關係沒有講到，老師預告下週會從這裡開始示範；以下先依講義整理。）

老師示範了一次完整的「用 AI 寫程式」流程，呼應前面「這門課對程式能力的要求」——重點在給 AI 精確的規格。示範提示詞是：

> 產生一段 Python 程式碼，其功能是提示使用者輸入 1~100 範圍內的整數（假設整數為 n），立即計算 1~n 的累加值並以 `print()` 函式輸出結果「從 1 至您輸入的整數值 n 的累加結果為: ...」。（若使用者輸入的字串不在限定的範圍內，或是非整數值，則以 `print()` 函式輸出一段警語）

AI（示範用 Google 搜尋的「AI 模式」）給出的程式沒有傻傻寫迴圈累加，而是直接套用等差級數公式：

```python
total = (1 + n) * n // 2
```

這個細節值得注意：精確的提示詞規格加上 AI 對演算法的理解，讓最終程式碼比「照著需求硬翻譯成迴圈」更精簡有效率——這正是「引導 AI 寫出對的程式」的具體樣子。範例程式存為 `01_1.py`。

### 載入 Iris Dataset 並顯示資料

延續前面「資料長什麼樣子」談到的 Iris 資料集，老師示範了兩種載入方式：
