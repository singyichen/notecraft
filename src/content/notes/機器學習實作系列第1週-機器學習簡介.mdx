課程分三塊：**理論**（術語與意義、原理與觀念、經典演算法）、**實作**（資料前處理與模型訓練流程、以 Python 程式實現）、**專題應用**（期末專案）。每堂課的節奏也對應這個分工：前半段講機器學習理論（資料前處理 → 傳統機器學習 → 模型選擇與評估 → 深度學習，難度依序遞增），後半段換成 Python 程式與套件的課堂實作。

### 先修科目

- **線性代數**：向量內積、矩陣乘法、矩陣轉置
- **微積分**：函數、微分（含連鎖律）、偏微分、梯度
- **（建議）Python**：型別、資料結構、條件邏輯與流程控制、函式與模組、物件導向程式設計

### 這門課對「程式能力」的要求

老師點出一個時代趨勢：現在大多數程式碼會由 AI 生成，單純「會打字寫程式」的能力（老師戲稱「碼農」——把寫程式比作像農夫一樣逐行敲打維護程式碼）已經不是重點，重點轉向**跨領域、能拆解複雜問題的系統設計能力**：專注在架構設計與問題拆解，剩下的交給 AI。因此這門課對程式能力的要求，不是「會不會寫」，而是**能不能引導 AI 寫出對的程式**——用精確的邏輯、規格與邊界條件下指令，並且有能力檢查 AI 生成的程式碼有沒有邏輯漏洞或安全風險。這個要求會直接體現在後面「AI 協助撰寫 Python 程式」這一節的示範裡。

## 本週摘要

### 什麼是機器學習？

傳統寫程式是「人工設計規則」：工程師把邏輯寫死進程式裡（例如「信件包含這幾個關鍵字，就判定為垃圾郵件」）。機器學習反過來——不寫死規則，而是給模型大量資料，讓模型自己從資料裡「歸納」出規律，再把歸納出的規律套用到新資料上。這個「從資料中歸納規律」的過程，就是「學習」。

機器學習模型通常帶有一組「可調參數」，訓練的過程就是不斷調整這些參數，讓模型在訓練資料上的預測誤差越來越小。

以老師舉的**眼底影像多標籤分類**為例：輸入一張眼底影像，模型 f(·) 要同時判斷它符不符合「正常」「糖尿病視網膜病變」「老年黃斑部病變」「青光眼」「白內障」「高血壓性視網膜病變」「病理性近視」「其他」這幾個標籤——一張影像可能同時符合多個標籤，所以是「多標籤」而非單一分類。機器學習要做的事，就是訓練出這個模型 f(·)。

### 監督式學習：有「標準答案」可以學

當訓練資料同時包含「輸入」與「正確答案（標籤）」時，屬於**監督式學習**——模型的任務是學會「輸入 → 標籤」這個對應關係，訓練完後套用在沒看過答案的新資料上。依標籤的型態，又分兩種：

- **分類（Classification）**：標籤是「離散的類別」，例如判斷一張圖片是貓還是狗、判斷一封信是垃圾郵件還是正常信件。模型輸出「屬於哪一類」。
- **迴歸（Regression）**：標籤是「連續的數值」，例如根據坪數、屋齡、地段預測房價、根據氣溫與濕度預測用電量。模型輸出一個數字。

分類跟迴歸的差異關鍵在「標籤的型態」，而不是模型的複雜度——同一種演算法（例如決策樹）稍加改造就能同時做分類跟迴歸。

### 非監督式學習：沒有標準答案，讓資料自己說話

當訓練資料**沒有標籤**時，屬於**非監督式學習**——模型的任務不是學一個對應關係，而是直接從資料本身的結構裡找出規律。常見兩種任務：

- **聚類（Clustering）**：把相似的資料點自動分成幾個群組，例如依購買行為把顧客分眾、依內容把新聞自動歸類主題。演算法要自己判斷「哪些資料算相似」，沒有人事先告訴它答案。
- **降維（Dimensionality Reduction）**：資料常有很多欄位（維度），但真正有意義的資訊可能只藏在其中幾個「潛在組合」裡。降維把高維度資料壓縮成更精簡的表示，同時盡量保留原本資料裡重要的結構——常用來把資料畫成 2D/3D 圖方便觀察，或替後續模型減少雜訊、加快訓練。

### 半監督學習：兩者之間的折衷

現實中「幫每一筆資料都標好答案」往往很貴（需要人工標註），但「收集大量沒有標籤的資料」通常很便宜。半監督學習拿少量標籤資料加上大量無標籤資料一起訓練，兼顧監督式學習的準確度與非監督式學習的低成本。

### 為什麼這套分類法重要

「監督式 vs 非監督式、分類 vs 迴歸、聚類 vs 降維」是機器學習領域的基本詞彙，因為拿到一個新問題時，第一件事就是先判斷「有沒有標籤」「標籤是類別還是數值」——這會直接決定該挑哪一類演算法、用什麼指標評估好壞：分類常看準確率／precision／recall，迴歸常看均方誤差（MSE）。

### 機器學習的典型任務：預測、降維、分群、生成

把前面談的分類法落到實際任務，機器學習大致做四件事：

- **預測（Prediction）**：分類（Classification，預測離散類別，例如判斷腫瘤良性或惡性）與迴歸（Regression，預測連續數值，例如預測明天氣溫）都屬於預測，差別只在標籤型態。
- **降維（Dimensionality Reduction）**：簡化複雜特徵，例如用特徵提取做資料壓縮。
- **分群 / 集群（Clustering）**：把相似的資料聚在一起，例如電商客群分群。
- **生成（Generation）**：創造出全新且合理的資料，例如文本、圖片與影音多媒體生成——這正是近年生成式 AI（GAI）的核心任務，也是「有無標籤」這套分類法之外，第四種獨立存在的任務型態。

前三種都能套進監督式／非監督式的框架（預測靠監督式學習，降維與分群靠非監督式學習），生成則是另一條路線，通常需要更龐大的資料與模型規模，這也是為什麼機器學習與人工智慧的關係（見後文）要另外拉出來談。

## 兩種更正式的定義

除了「有沒有標籤」這個實務分類法，機器學習還有兩種常被引用的定義，分別從「效能」與「函式」兩個角度切入：

- **Tom Mitchell 的定義**：一個電腦程式在面對某項任務（Task）時，如果其效能表現（Performance）隨著經驗（Experience）的增長而提升，就說這個程式具備學習能力。
- **李宏毅的定義**：讓機器具備「找一個函式（Function）」的能力——透過訓練資料，讓電腦自動尋找能解決特定問題的未知函式（帶有未知參數的函式，稱為參數化模型）。

這剛好呼應前面提到的「可調參數」：訓練的本質就是在調整模型（一個帶未知參數的函式）裡的參數，讓它在訓練資料上的預測誤差越來越小，也就是 Mitchell 定義裡「效能隨經驗提升」的具體做法。

## 核心術語一次搞懂

初學機器學習常卡在術語上，這裡把老師在第一堂課列出的「常見（易混淆）術語」全部定義一次；其中有些要等到對應週次才會實際動手操作（梯度下降、反向傳播、正則化等），先在這裡建立定義，之後會用程式範例把它們串起來。

### 模型與資料的基本組成

- **Model（模型）**：機器學習的核心實體，一個數學公式或演算法結構，負責學習資料中的規律——也就是訓練要找出來的那個函式。
- **Sample（樣本）**：資料集中的一筆觀測紀錄，對應表格的一橫列。
- **Feature（特徵）**：描述樣本的屬性或維度，對應表格的一直欄，也稱輸入或變數。
- **Target / Label / Ground truth（目標／標籤／真實答案）**：模型要預測的答案。Label 通常指資料集裡附帶的標籤，Ground truth 則強調它是「真實」答案。

### 特徵前處理

- **Feature scaling（特徵縮放）**：訓練前把不同量級的特徵拉到同一個尺度，讓每個特徵公平參與計算，避免數值範圍大的特徵主導模型。
  - **Normalization（正規化）**：把特徵線性縮放到固定範圍（通常是 [0, 1]），公式為 `(x - min) / (max - min)`；缺點是對離群值（outlier）敏感，一個極端值就會壓縮其他資料的分布範圍。
  - **Standardization（標準化）**：把特徵轉換成平均值 0、標準差 1 的分布，公式為 `(x - mean) / std`（也稱 z-score normalization）；不設固定上下限，對離群值較穩健，是深度學習與多數線性模型更常用的做法。
- **Feature selection（特徵選取）v.s. Feature extraction（特徵提取）**：選取是從原始特徵中挑出有用的子集（欄位不變，只是刪減）；提取則是把原始特徵組合、轉換成新的、更精簡的特徵（例如 PCA 降維），欄位本身已經改變。

### 訓練流程的基本節奏

- **Trainable parameters（可訓練參數，含 weights 權重與 bias unit 偏差項）v.s. Hyperparameters（超參數）**：前者是模型在訓練過程中自動從資料學出來的參數；後者是訓練開始前由人手動設定、用來微調模型表現的參數（例如學習率、樹的深度、batch size）——調校模型時真正能「手動控制」的只有超參數。
- **Training（訓練，亦稱 Model fitting）**：用訓練資料反覆調整可訓練參數，讓模型在訓練資料上的預測誤差變小的過程。
- **Epoch**：訓練過程中把整份訓練資料完整跑過一輪，稱為一個 epoch；模型通常需要跑過多個 epoch 才會收斂。
- **Validation（驗證）**：用另一批不參與訓練的資料，檢查目前模型或超參數設定的表現，作為調整依據。
- **Testing（測試）**：訓練與調整都定案後，最後拿一份從頭到尾都沒被用過的資料，評估模型對「全新資料」的最終預測能力。三者（Training／Validation／Testing）不可混用。

### 梯度下降家族

- **Loss function（損失函數）**：衡量模型預測值與 ground truth 之間差距的函數，數值越小代表預測越準；訓練的目標就是調整可訓練參數，讓 loss function 在訓練資料上最小化（迴歸常用均方誤差 MSE，分類常用 cross-entropy）。
- **Activation function（激活函數）**：神經網路中每個神經元完成線性加權運算後套用的一個非線性函數（例如 sigmoid、ReLU、tanh），作用是讓網路能表達非線性關係——沒有它，再多層的網路疊起來仍等價於一層線性運算。
- **Gradient descent（梯度下降，亦稱 Full-batch / Batch gradient descent）v.s. Stochastic gradient descent（SGD，隨機梯度下降）**：梯度下降每次更新參數前，用「全部」訓練樣本計算 loss 的梯度再往反方向調整，方向穩定但資料量大時計算成本高；SGD 每次只用「一筆」隨機抽樣的樣本就更新參數，更新快、有機會跳出局部最低點，但方向震盪較大。
- **Mini-batch v.s. Full-batch**：兩者的折衷——mini-batch 每次用一小批樣本（例如 32、64、128 筆）計算梯度後更新，兼顧計算效率與穩定性，是深度學習最常用的方式；full-batch 就是前面說的梯度下降，用全部樣本。
- **Backpropagation（反向傳播）**：訓練神經網路時，用連鎖律（chain rule）從輸出層往輸入層反向、逐層計算 loss 對每個參數的梯度的演算法，是梯度下降能有效率套用在多層網路上的關鍵技術。

### 模型選擇、驗證與評估

- **Model selection（模型選擇）**：在多個候選演算法或超參數組合之間，挑出表現最好的那一個。
- **Model validation（模型驗證）**：用驗證集評估模型在「沒訓練過的資料」上的表現，作為 model selection 的依據，避免只憑訓練集的表現做決策。
- **Model evaluation（模型評估）**：用適當的指標（accuracy、precision、recall、F1-Score、MSE 等）衡量模型好壞，通常在最後的測試階段進行，得出模型的最終評估結果。

### 診斷曲線

- **Loss curve（損失曲線）**：橫軸是訓練迭代次數（iteration / epoch），縱軸是 loss 值，用來看模型有沒有正確收斂（loss 應持續下降）。
- **Learning curve（學習曲線）**：橫軸是訓練樣本數量，縱軸是模型在訓練集／驗證集上的表現，用來診斷模型是否需要更多資料，或有 high bias／high variance 的問題。
- **Validation curve（驗證曲線）**：橫軸是某個超參數的數值（例如樹的深度、正則化強度），縱軸是訓練集／驗證集的表現，用來找出該超參數的最佳設定值，是 model selection 常用的診斷工具。

### 過擬合與正則化

- **Overfitting（過擬合，high variance）**：模型過度擬合訓練資料裡的細節與雜訊，在訓練集表現很好、但在驗證／測試集表現明顯變差——模型「記住」了訓練資料，而不是學到通則。
- **Underfitting（欠擬合，high bias）**：模型太簡單，連訓練資料本身的規律都學不好，訓練集與驗證集的表現都不理想。
- **Regularization（正則化）**：在 loss function 中加入一個懲罰項，限制可訓練參數（權重）不要過大，藉此抑制模型複雜度、緩解 overfitting，常見作法有 L1、L2 正則化。
- **Dropout（失活）**：訓練神經網路時，每次迭代隨機「關閉」（失活）一部分神經元（不參與這次的前向與反向傳播），迫使網路不能過度依賴少數幾個神經元，是深度學習裡常見的 overfitting 對抗手法。

## 資料長什麼樣子——以 Iris 資料集為例

判斷一份資料能用什麼方法處理，通常從三個角度分類：

- **有無結構**：結構化資料（如二維表格、關聯式資料庫）欄位固定；非結構化資料（文字、圖片、影音）沒有固定欄位；半結構化資料（JSON、XML）介於兩者之間，靠標籤或 key-value 表達層級。
- **有無標籤**：有標籤資料每筆都附正確答案（監督式學習的原料）；無標籤資料只有特徵、沒有答案（非監督式學習的原料）。
- **數學特性**：數值型資料分連續（身高、房價）與離散（房間數）；類別型資料分名義型（性別、血型，沒有順序）與順序型（學歷、滿意度，有順序）。

機器學習領域的經典入門資料集 **Iris（鳶尾花）** 剛好是這三個分類的教科書範例：150 筆觀測、每筆是結構化的一橫列，4 個連續數值型特徵（花萼長寬、花瓣長寬，單位 cm），加上 1 個名義型類別標籤（Setosa / Versicolor / Virginica 三種鳶尾花），且資料乾淨、沒有缺失值，所以常被拿來當分類與分群演算法的基準測試。

## 強化式學習——第三種學習方式

前面談的監督式／非監督式學習都是從「靜態資料」裡學規律，但還有一種**強化式學習（Reinforcement Learning, RL）**：代理人（Agent）透過與環境（Environment）互動、採取行動（Action）、試錯（trial-and-error），並根據獲得的獎勵（Reward）去學習一套能讓總獎勵最大化的策略。

RL 跟監督式學習的關鍵差異在於「回饋的型態」：監督式學習有明確的正確標籤可以直接比對誤差；RL 沒有標準答案，只有一個衡量「這個行動好不好」的獎勵函數，而且獎勵有時是延遲的（做了一連串動作後才知道好壞），例如 AlphaGo 下圍棋要等一整盤棋下完才知道輸贏。

## 建立機器學習系統的工作流程

以監督式學習的預測建模為例，建立一套機器學習系統不是「選一個演算法訓練完就結束」，而是一個會反覆調整的迴圈：

1. **選擇特徵並收集帶標籤的訓練樣本**
2. **選擇效能指標**——例如正確率（Accuracy）、精準率（Precision）、召回率（Recall）、F1-Score
3. **選擇機器學習演算法並訓練模型**——通常先由這一步切入，之後再回頭處理其他議題
4. **評估模型的效能**——從訓練樣本中抽出一部分作為驗證集（不參與訓練），拿來評估表現
5. **調整演算法設定並優化模型（或更換演算法）**——也就是調整超參數

這五步不是線性跑一次就結束：第 4 步評估完若表現不理想，會回到第 5 步調整超參數、甚至回到第 3 步換一個演算法，形成一個迴圈。

背後的原因是機器學習領域公認的 **No Free Lunch 定理**：不存在一個分類器能在所有可能的場景下都表現最好。因此正確的做法是**至少比較幾種不同的機器學習演算法**，才能替手上這個具體問題挑出最適合的模型——這也是為什麼「選擇機器學習演算法並訓練模型」在流程裡通常不會只做一次。

## 機器學習與人工智慧的關係

人工智慧（AI）是一個終極目標，因為目標太遠大，實際上會分階段逐步邁進；機器學習（ML）則是達成這個目標的其中一種**手段**——ML 把資料轉換成知識，深度學習（Deep Learning, DL）又是 ML 底下特別強大的一種手段。

| AI 階段 | 代表技術／概念 | 核心能力 |
| --- | --- | --- |
| 當前階段 | GAI（生成式 AI） | 內容的創造與文字／影像生成 |
| 現在～近未來 | AI Agent（代理人） | 自主規劃步驟、使用工具完成線上任務 |
| 下一階段（躍升） | Physical AI（具身智能） | 結合硬體與機器人，在物理世界採取行動 |
| 終極目標 | AGI／ASI（通用／超級 AI） | 跨領域自學、自我反思，達到或超越人類智慧 |

AGI（Artificial General Intelligence，通用人工智慧）與 ASI（Artificial Superintelligence，超級人工智慧）是這條演進路線的終點；目前普遍認為正處在「生成式 AI 邁向 AI 代理人」的階段。這張分期表也解釋了這門課的位置：機器學習是整條路線最基礎、最核心的手段，不管未來走到哪個階段，都是建立在這門課教的觀念與方法上。

## Python 環境建置

這堂課後半段開始進入實作，第一步是把 Python 開發環境建起來。

### 開發環境的組成

- **Python 主程式**：包含直譯器（Interpreter，`python.exe`）、套件管理工具 `pip`、以及內建的標準函式庫
- **IDE（整合式開發環境）**：課程推薦輕量且強大的 **Visual Studio Code**，負責程式碼編輯、編譯／直譯、連結、執行、除錯
- **外部函式庫（第三方套件）**：NumPy、SciPy、Pandas、Matplotlib、Scikit-learn、PyTorch 等
- **（選用）虛擬環境（Virtual Environment）**：為不同專案建立獨立的套件庫，避免版本衝突

Python 之所以在資料科學圈這麼流行，除了語法親和，關鍵是**大量科學計算與機器學習函式庫**：NumPy／SciPy 做科學計算、Pandas／Matplotlib 做資料分析與視覺化、Scikit-learn／PyTorch 做機器學習與深度學習。缺點是直譯式語言效能不如低階語言，但 NumPy／SciPy 底層建立在 Fortran 與 C 之上、能做快速向量化運算，PyTorch 又能透過 GPU 有效率訓練深度神經網路，某種程度彌補了這個劣勢。

### 建置步驟

1. **安裝 Python 主程式**：從 Python 官網下載安裝檔（依作業系統選擇），安裝時務必在視窗底部**勾選「Add python.exe to PATH」**，再點擊「Install Now」。裝完打開終端機輸入 `python --version`，能正確顯示版本號（例如 `Python 3.14.6`）就代表成功。
2. **安裝 VS Code**：從官網下載對應作業系統與處理器架構（x64／Arm64／…）的安裝檔，直接執行安裝。裝好後在「擴充功能（Extensions）」搜尋 Python，安裝微軟開發的三個套件：**Python**（官方核心套件）、**Pylance**（語法補全與靜態型別檢查）、**Python Debugger**（中斷點、變數監控、逐行除錯），以及獨立出來的 **Python Environments**（虛擬環境管理）。裝完記得重啟 VS Code。接著用 `Ctrl+Shift+P` 開命令面板，搜尋「Python: Select Interpreter」選擇剛才安裝的 Python 版本。
3. **安裝外部函式庫**：在 VS Code 下方 Panel 開啟 TERMINAL 頁籤，執行：

   ```bash
   python -m pip install -U numpy matplotlib seaborn scipy pandas scikit-learn torch torchvision
   ```

   等 pip 依套件相依性下載安裝完成即可。

### 撰寫與執行第一支 Python 程式

在專案資料夾（例如 `Machine Learning`）中用 VS Code 開啟，新增一個以 `.py` 為副檔名的原始碼檔案（例如 `hello.py`），寫入：

```python
print("Hello, World!")
```

點視窗右上角的「▷」（Run Python File）按鈕執行，TERMINAL 會輸出 `Hello, World!`。

### AI 協助撰寫 Python 程式

老師示範了一次完整的「用 AI 寫程式」流程，呼應前面「這門課對程式能力的要求」——重點在給 AI 精確的規格。示範提示詞是：

> 產生一段 Python 程式碼，其功能是提示使用者輸入 1~100 範圍內的整數（假設整數為 n），立即計算 1~n 的累加值並以 `print()` 函式輸出結果「從 1 至您輸入的整數值 n 的累加結果為: ...」。（若使用者輸入的字串不在限定的範圍內，或是非整數值，則以 `print()` 函式輸出一段警語）

AI（示範用 Google 搜尋的「AI 模式」）給出的程式沒有傻傻寫迴圈累加，而是直接套用等差級數公式：

```python
total = (1 + n) * n // 2
```

這個細節值得注意：精確的提示詞規格加上 AI 對演算法的理解，讓最終程式碼比「照著需求硬翻譯成迴圈」更精簡有效率——這正是「引導 AI 寫出對的程式」的具體樣子。範例程式存為 `01_1.py`。

### 載入 Iris Dataset 並顯示資料

延續前面「補充：資料長什麼樣子」談到的 Iris 資料集，老師示範了兩種載入方式：
