## 課堂版定案（期末發表範圍）

2026-10-19 討論後定案。期末發表只做英文、只做一個子資料集，問題形式化沿用下方「論文延伸」的定義，其餘延伸項目全部留到論文。

登記表單用的主題名稱（短版，不綁定論文題目）：

> 部分標註下的標註分歧預測與複核排序

白話一句話：

> 資料標註時，一題會發給好幾個人標。這個專案要做的是：**在只拿到前兩個人的答案時，就先猜出這題最後會不會「大家標不一樣」**，把最可能吵起來的題目排到前面，讓負責複核的人先看。

正式的研究問題：

> 一筆資料只取得前 2 份標註時，能否預測完整標註是否會出現分歧，並且勝過只看這 2 份標註的簡單規則？

### 問題的場景

想像標註平台上的場景。一則 Reddit 留言發給 3 個人標它的情緒是正面、負面、模糊還是中立。有些留言 3 個人答案一模一樣，那就沒事；有些留言兩人說中立、一人說正面——這種題目才需要人工進去確認，是標註規範沒寫清楚，還是這題本身就有爭議。

問題在於：要等 3 個人全標完，才知道哪些題會吵。但標註是陸續進來的，能複核的人力又有限。所以要做的是一個提早預警：只看前 2 個人的答案加上留言本身的文字，先算出「這題會吵的機率」，再照機率排序，複核的人從最上面開始看。

這與論文和正在做的標註平台（Label Suite）直接相關：平台之後要處理「標註進來後哪些該送複核」，需要先知道這件事用機器學習值不值得、以及要先記下哪些欄位。期末專案是把這個問題縮到一學期能跑完的版本。

### 為什麼不是「看前兩個人有沒有吵」就好

那是最直覺的做法，也正是本專案的對照組之一。但它只抓得到已經明顯的那種分歧，真正有價值的是另一種題目：**前兩個人剛好意見一致，但其實是爭議題**——這種題用規則會被判成安全，直接漏掉。

實測資料（見「子資料集定案」一節）的數字是：隨機揭露 2 份標註後，66.6% 的題目「前兩人一致」，而這些題裡有 24.4% 的第三位標註者最後給了不同答案。只看前兩人一不一致，這四分之一的爭議題全部會被判成安全。

### 任務形式

二元分類，模型輸出的機率再用來排序。

| 元素 | 內容 |
| --- | --- |
| 一筆資料 | 一則 Reddit 留言 |
| 特徵 | 留言文字（TF-IDF）＋前 2 份標註的資訊（兩人是否一致、標了什麼） |
| 要預測的答案 | 完整標註最後有沒有出現分歧（$z_i$） |
| 輸出怎麼用 | 機率由高到低排序，當成人工複核的優先順序 |

資料是 TID-8 的 goemotions 子資料集：英文 Reddit 留言的情緒標註，標籤是 positive、negative、ambiguous、neutral 四類，每則恰好 3 個人標過，而且**完整保留了「哪一位標註者標了哪一題、標了什麼」**。這點是關鍵——多數公開資料集只給投票後的最終答案，那就無法研究分歧如何形成。上游授權是 Apache-2.0，定案理由與完整統計見「子資料集定案」一節。

### 對應簡報六段

| 簡報段落 | 課堂版內容 |
| --- | --- |
| 問題描述 | 二元分類：完整標註是否出現分歧（$z_i$），模型輸出的機率再用來排序複核優先順序 |
| 資料收集 | TID-8 的 goemotions 子資料集（`-atr` config，原始出處為 Demszky et al. 2020，Apache-2.0）；說明原始出處、4 類分組的由來、標註方式與授權 |
| 資料分析與前處理 | 篩出恰好 3 份標註的 item、丟掉 `author`、文字去重；統計 item 數、annotator 數、分歧比例、類別分布；以 `item_id` 分組切分 70／15／15；每題隨機揭露 2 份標註；文字轉 TF-IDF |
| 模型訓練 | 照下方「模型階梯」四層由笨到聰明比下去，以 `GridSearchCV` 搭配 `GroupKFold` 調參 |
| 模型評估 | PR-AUC、`Recall@10%`、混淆矩陣；5 個 reveal seeds 報平均 ± 標準差 |
| 結論 | 機器學習是否勝過 entropy 規則，並挑出模型判斷錯誤的案例分析原因 |

主要指標 `Recall@10%` 的意思是「排前 10% 能抓到多少爭議題」，因為實務上的問句就是「今天只有時間複核 10% 的題目，幫我排」。

### 模型階梯

| 階梯 | 方法 | 用途 | 超參數 |
| --- | --- | --- | --- |
| 0 | 隨機排序 | 地板線 | 無 |
| 1 | 可見標籤 entropy（只看前 2 份一不一致） | 「不用機器學習」的對照組 | 無 |
| 2 | Logistic Regression | 第一個真正的 ML 模型 | `C` |
| 3 | Random Forest 或 Gradient Boosting | 檢查非線性模型有無額外增益 | RF 調 `n_estimators`、`max_depth`；GB 調 `n_estimators`、`learning_rate`、`max_depth` |
| 4（選做） | 零樣本大語言模型 | 回答「LLM 是不是早就會了」，設定與限制見論文延伸的「大語言模型對照線與資料污染」 | 無（只調提示詞） |

特徵與調參的設定：

| 項目 | 內容 |
| --- | --- |
| 文字特徵 | TF-IDF 為主線 |
| 可見標註特徵 | 前 2 份標註是否一致、可見標籤 entropy |
| 加一行比較（選做） | 把 TF-IDF 換成 `BAAI/bge-m3` Embedding，先以 PCA 降維再接分類器 |
| 調參評分 | 直接用主要指標 `Recall@10%`，只在訓練集內以 `GroupKFold` 交叉驗證，測試集只在最後評估一次 |

`GroupKFold` 的 group 必須是 `item_id`。若改用一般的 `KFold`，同一題被揭露的不同 reveal seed 可能同時落在訓練折與驗證折，調參分數會偏高。

### 結論會長什麼樣

兩種走向都算完整結果，這是刻意這樣設計的：

- ML 明顯勝過「看前兩人一不一致」→ 值得在標註平台加一個排序功能。
- ML 勝不過規則 → 就用那條透明的規則，不要為了用模型而用模型。這個結論同樣有價值，而且省下維護成本。

## 子資料集定案：GoEmotions

2026-10-19 定案。同一天先依實測數字選過 md-agreement，後來因為授權問題改定：**課堂版採用 TID-8 的 goemotions 子資料集，並只取「恰好 3 份標註」的 item**。

改定的理由是取得方式與授權：md-agreement 的上游沒有開源授權、限非商業研究、必須填表單向作者申請，而 TID-8 的轉散佈版授權欄標示 `unknown`，這條鍊在論文公開階段站不住。GoEmotions 的上游是 Apache-2.0、可直接下載。實測之後還發現它的目標分布比 md-agreement 更平衡，所以這個改動不是退讓。

以下統計以 TID-8 在 Hugging Face 上的 parquet 檔為來源，train 與 test 合併計算（因為本專題要自己重切），腳本與資料不進 repo。

### 候選的授權與取得方式

| 項目 | GoEmotions（GOE，定案） | md-agreement（MDA） | sentiment（SNT） |
| --- | --- | --- | --- |
| 原始論文 | Demszky et al. 2020,《GoEmotions》（[ACL 2020](https://aclanthology.org/2020.acl-main.372/)） | Leonardelli et al. 2021,《Agreeing to Disagree》（[EMNLP 2021](https://aclanthology.org/2021.emnlp-main.822/)） | Díaz et al. 2018,《Addressing Age-Related Bias in Sentiment Analysis》（CHI 2018；[IJCAI 轉載](https://www.ijcai.org/proceedings/2019/852)） |
| 原始資料位置 | [google-research-datasets/go_emotions](https://huggingface.co/datasets/google-research-datasets/go_emotions)（`raw` config 保留 `rater_id`） | [dhfbk/annotators-agreement-dataset](https://github.com/dhfbk/annotators-agreement-dataset/) | [Harvard Dataverse DOI:10.7910/DVN/F6EMTS](https://dataverse.harvard.edu/dataset.xhtml?persistentId=doi:10.7910/DVN/F6EMTS) |
| 取得方式 | 直接下載 | 不可直接下載，須填表單向作者申請 | 直接下載 |
| 授權 | **Apache-2.0** | 無開源授權；限非商業研究、不得用於側寫或針對個人、受 Twitter 開發者政策約束 | CC0 1.0（公眾領域） |
| 內容 | Reddit 留言的情緒標註。原始為 27 類多標籤，TID-8 依原作者的分組壓成 4 類單標籤：positive、negative、ambiguous、neutral | 英文推文的攻擊性言論標註，三領域（BLM、Elections2020、Covid-19） | Sentiment140 推文子集，由不同年齡層標註者重新標 5 級情緒 |

TID-8 的 Dataset Card 授權欄是 `unknown`，其論文也沒有授權聲明，只有 Ethics Statement 說明八個子資料集都是既有的公開資料。所以授權一律要追到原始出處；追完才看得出三者差距很大。

GoEmotions 的 4 類分組是 TID-8 依 Demszky 等人的做法做的（論文附錄 B.3），不是本專題自己合併的，Dataset Card 要寫明這一點。

| 三人三種標籤 | 1.3% |
| 二分圖連通分量 | 1 個，涵蓋 100% |
| 文字長度（字元） | Q1 34、中位數 60、Q3 91、P95 130、最長 703 |
| 重複文字 | 163 筆（31,766 個 item 對應 31,603 段不同文字） |
| 其他可用欄位 | `subreddit`（483 個）、`author`、原始 27 個情緒欄位 |

整個 goemotions config 有 57,703 個 item、193,633 筆標註，但每題標註數從 1 到 5 不等。只取恰好 3 份的 31,766 題，是為了讓分母固定——這樣就沒有「標註數本身洩漏答案」的問題，entropy 的分母也一致。

### 分歧的型態

| 三人的標籤組合 | item 數 | 佔比 |
| --- | --- | --- |
| positive（全一致） | 8,691 | 27.4% |
| neutral＋positive | 5,756 | 18.1% |
| negative＋neutral | 4,199 | 13.2% |
| neutral（全一致） | 3,320 | 10.5% |
| negative（全一致） | 2,981 | 9.4% |
| ambiguous＋neutral | 2,613 | 8.2% |
| negative＋positive | 1,322 | 4.2% |
| ambiguous（全一致） | 1,002 | 3.2% |

分歧集中在語意相鄰的類別——neutral 與 positive、neutral 與 negative、ambiguous 與 neutral——而真正相反的 negative 與 positive 只佔 4.2%。這是錯誤分析那一段的現成材料：模型抓不到的應該多半是相鄰類別的邊界題，而不是極性顛倒。

### 揭露 2 份之後的難度

真正要預測的是「可見的 2 份標註一致，但第三位會偏離」這個子集——可見已經不一致的題目必然分歧，規則不用學就全對，沒有研究價值。5 個 seed 的實測：

| seed | 可見一致的 item | 其中第三位偏離 |
| --- | --- | --- |
| 0 | 21,165（66.6%） | 5,171（24.4%） |
| 1 | 21,083（66.4%） | 5,089（24.1%） |
| 2 | 21,157（66.6%） | 5,163（24.4%） |
| 3 | 21,195（66.7%） | 5,201（24.5%） |
| 4 | 21,169（66.6%） | 5,175（24.4%） |

難題子集的陽性率 24.4%，是四個候選裡最適合排序任務的：預算 10% 而地雷佔 24%，排得好不好差別明顯。對照其他候選的同一個數字——md-agreement 59.0%、sentiment 82.2%、CommitmentBank 93.6%——越接近 100% 就越是「不管怎麼排都會撞到」，`Recall@10%` 讀不出模型能力。

### 為什麼不是另外三個

| 候選 | 排除原因 |
| --- | --- |
| md-agreement | 授權：上游限非商業研究且要填表單，TID-8 轉散佈版標 unknown。數字本身是合格的（6,592 item、819 annotator、單一連通分量、難題陽性率 59.0%），所以保留為論文階段的第二資料集候選——跨資料集穩健性那一章用得上，屆時照流程申請原始檔 |
| sentiment | 目標退化：93.7% 的 item 有分歧，難題子集陽性率 82.2%，壓成三類仍有 87.3%。而且每位標註者固定標 40 題，圖被切成 305 個互不相連的批次、最大一塊只涵蓋 1.9% 的 item，annotator 歷史與 GraphSAGE 都不成立。TID-8 論文自己的結果也印證這點：annotator split 下 SNT 的 annotation embedding 效能大幅衰退 |
| CommitmentBank | 只有 1,200 個 item（剛好卡在門檻）、7 類序數標籤讓分歧率高到 97.9%（壓成三類才降到 79.4%）、文本是 326 字元的長段落，授權也查不到明確聲明 |

### 選 GoEmotions 要付的代價

| 代價 | 處理方式 |
| --- | --- |
| 只有 79 位 annotator | 無法像 md-agreement（819 位）那樣研究「對沒見過的新 annotator 泛化」，論文的冷啟動實驗要降級為探索性結果。但每位標了平均 1,206 題，annotator 歷史特徵反而比 md-agreement 更充足 |
| 隱藏只剩 1 份標註 | target 的語意是「第三位會不會偏離前兩位」，比隱藏 3 份更噪；也算不出有意義的完整 entropy $H_i$（只有 3 個標籤），所以主要 target 固定用「任何分歧」，不使用 $H_i \ge \tau$ 的門檻版本 |
| 4 類是 TID-8 的分組 | 原始是 27 標籤多標籤，Dataset Card 要寫明分組依據與來源 |
| 含 Reddit 使用者名稱 | `author` 欄位是個資，載入後立刻丟棄；`subreddit` 保留當穩健性軸（前五大 subreddit 的分歧率在 42.1% 到 54.2% 之間） |
| 標註數 1 到 5 份不等 | 只用恰好 3 份的子集。**不要把 5 份的 12,424 題混進來**——那是「不清楚的例子被加標」造成的，分歧率衝到 85.5%，標註數本身就洩漏答案 |
| 163 筆重複文字 | 切 split 前先以文字去重或合併，避免同一段文字同時落在 train 與 test |

### 順帶驗證到的兩件事

**自帶 split 不能用**。`goemotions-atr` 的 test item 有 96.0% 同時出現在 train（`sentiment-ann` 是 100%、`md-agreement-atr` 是 99.7%）。TID-8 的兩種切法都是為了研究「從分歧中學習」設計的，不是為本專題的排序任務設計的，所以一律自己以 `item_id` 重切。

**goemotions 的兩個 config 資料量相同**。`goemotions-ann` 與 `goemotions-atr` 都是 193,633 筆，差別只在切法（`-atr` 的 25 位 test annotator 與 train 完全不重疊）。因為我們自己重切，取哪一個都可以；為與上面的統計一致，固定取 `-atr`。這與 md-agreement 不同——那個資料集的 `-ann` 版砍掉了約 12% 的標註。


## 論文延伸：預測標註者分歧，協助安排複核

> 以下是完整的八階段研究規劃，期末發表只取用其中的問題形式化與階段 1–4 的核心設定（見上方「課堂版定案」）。繁中 pilot、annotator 歷史、多語 Embedding 雙語比較與 GraphSAGE 都在期末之後、作為論文延伸進行。

### 題目與方案決策

期末專案正式採用**方案 B：真實多標註者資料 + 多語文字 Embedding + 傳統分類模型，GNN 作為選做比較**。

暫定題目：

> **部分標註下的複核排序：標註分歧預測方法比較與標註平台資料需求**

2026-10-19 調整過標題的重心。原本的題目是「以文字特徵與標註歷史預測標註分歧：英文與繁體中文複核排序之比較研究」，主標題落在「預測標註分歧」——那正是 Le-Wi-Di 這個 shared task 已經做過的部分（見下方「相關工作」），而真正沒被做掉的兩個差異（只看到部分標註、以及平台要先記下什麼）反而沒出現在標題裡。研究設計一字未改，只是把宣告的重心換到差異點上。

Label Suite 尚未正式累積真實使用紀錄，因此期末階段先以公開的真實多標註者資料驗證方法，再建立一份小型繁體中文 pilot。這兩條證據的角色不同：英文公開資料回答「方法在真實多標註資料上是否可行」，繁中 pilot 回答「方法能否轉移到論文的主要使用者情境」。

| 層級 | 必要性 | 內容 |
| --- | --- | --- |
| 真實英文資料 | 必做 | 從 TID-8 選一個保留 `item_id`、`annotator_id` 與個別標籤的子資料集 |
| 繁體中文 pilot | 必做 | 從論文目標情境抽取 150 至 300 筆文字，每筆由至少 3 位標註者獨立標註 |
| 隨機與規則基準 | 必做 | 隨機排序、可見標籤熵、票數差距與簡單統計 |
| 傳統分類模型 | 必做 | Logistic Regression 與 Gradient Boosting |
| 多語 Embedding | 必做 | 以同一模型處理英文與繁中；本機模型優先，外部 API 作選配對照 |
| GraphSAGE | 選做 | 驗證 item–annotator 圖結構是否有穩定額外效益 |
| 完整 Label Suite 功能 | 不做 | 本專題只做離線原型與資料需求建議，不開發正式複核佇列 |

專題目標是**排序較可能出現分歧的資料項目**，不是取代標註者、裁定哪一個標籤正確，也不把分歧直接等同於標註錯誤。

### 相關工作：Le-Wi-Di 與本專題的差異

「不要聚合成單一真值、直接從分歧中學習」已經是一個成熟的研究方向：[SemEval-2023 Task 11（Le-Wi-Di，Learning With Disagreements）](https://arxiv.org/pdf/2304.14803) 以四個保留逐人標註的資料集辦過 shared task（其中的 md-agreement 正是本專題一度選定的候選），有數十支隊伍的系統論文；GoEmotions 雖然不在那四個之中，但同樣是 TID-8 與 soft label 文獻反覆使用的資料集。因此「機器學習能不能預測標註分歧」不能當成本專題的新發現，必須明確引用並指出差異：

| 面向 | Le-Wi-Di 與多數既有文獻 | 本專題 |
| --- | --- | --- |
| 預測時點 | 拿到完整標註後，估計該題的 soft label 分布（事後擬合） | 只拿到 $r$ 份標註時預測剩下的會不會分歧（提早預警），主要設定 $r=2$ |
| 目標 | 擬合標籤分布，指標是 cross-entropy 與 micro-F1 | 在固定複核預算下排序，指標是 `Recall@K` 與 PR-AUC |
| 可用資訊 | 文字（部分系統另加 annotator 身分） | 文字＋當下已可見的標註＋annotator 歷史與圖結構，且嚴格禁止使用隱藏標註 |
| 產出 | 模型與排行榜成績 | 模型比較結果，加上標註平台要記下哪些欄位才重建得出「當時可見的資訊」 |
| 語言 | 英文與阿拉伯文 | 英文公開資料加上臺灣繁體中文 pilot |

因此本專題宣告兩個貢獻，順序如下：第一是**部分觀測下的複核排序**這個問題設定與方法比較；第二是**標註平台的資料需求規格**（見「階段 8」的 Label Suite 未來資料需求）。分歧預測本身只是達成前者的手段，不單獨當成貢獻。

### 大語言模型對照線與資料污染

必須回答「這件事現在的大語言模型是不是早就會了」。文獻的現況是：零樣本 LLM 能給出不錯的**單一標籤**，但預測**人類分歧的分布與不確定性**時與人類有系統性落差，而且靠放大模型解決不了，需要 in-domain 微調才拉得近；硬標籤預測會塌成單峰，即使人類實際意見分裂。這正好與本專題的主張互補——分歧訊號有一部分不在文字裡，而在「誰標了、已經標成什麼」。

| 項目 | 設定 |
| --- | --- |
| 做法 | 給 LLM 留言文字與已可見的 2 份標註，要它輸出 0 到 1 的分歧機率 |
| 報告內容 | 與其他階梯同一條 `Recall@10%`，另加校準（ECE 或 reliability diagram） |
| 定位 | 課堂版選做、論文階段必做；當成階梯最上面一層，不是主線模型 |
| 必寫的限制 | GoEmotions 公開且被大量使用，LLM 幾乎確定在預訓練時見過這些留言甚至標籤，因此其分數不可檢驗，要寫明資料污染風險 |
| 資料治理 | GoEmotions 是 Apache-2.0，送外部 API 沒有授權障礙，但必須先丟掉 `author`（Reddit 使用者名稱）；成本考量下可只送測試子樣本，或改用可本機執行的開源模型 |

### 英文與繁體中文能否一起處理

可以，但要把「模型支援中文」與「研究已證明繁中有效」分開。

多語 Embedding 可以把英文與中文映射成同維度向量，下游的 Logistic Regression、Gradient Boosting 或 GNN 都只接收數值特徵，因此技術管線可以共用。然而模型宣稱支援 `zh`，不代表它一定掌握臺灣繁體中文的用詞、標點、語氣與領域術語；仍需要繁中資料獨立驗證。

建議的 Embedding 選型如下：

| 模型 | 定位 | 專題角色 | 注意事項 |
| --- | --- | --- | --- |
| [`BAAI/bge-m3`](https://huggingface.co/BAAI/bge-m3) | 開源多語 Embedding，1024 維、MIT License | **推薦作主模型**，可本機一次處理英文與中文 | 官方資料以 `zh` 為單位，仍要用臺灣繁中 pilot 驗證 |
| [`voyage-4-lite`](https://docs.voyageai.com/docs/embeddings) | 多語 Embedding API，偏成本與延遲效率 | 有額度時作 API 對照 | 公開資料可送 API；論文真實資料需先確認資料治理 |
| [`mistral-embed`](https://docs.mistral.ai/studio/knowledge-rag/embeddings) | 通用文字 Embedding API | Voyage 的替代方案，不需要兩者都做 | 不使用 Mistral 對話模型產生判斷 |

`BGE-M3` 的論文與模型卡描述其多語能力涵蓋超過 100 種語言，且可本機產生 dense embedding。這適合論文以繁體中文為主的情境：英文與繁中可以共用同一特徵產生器，也不必把尚未確認可外傳的文字送到第三方 API。[BGE-M3 論文](https://arxiv.org/abs/2402.03216)

雙語實驗要分成三種，不混成一個模糊的「多語結果」：

1. **英文單語模型**：在英文 TID-8 訓練與測試，驗證方法可行性。
2. **繁中單語模型**：在繁中 pilot 交叉驗證，回答論文主要使用情境。
3. **跨語轉移實驗**：英文訓練、繁中測試，或英文與繁中合併訓練；只當探索性結果，不取代繁中單語驗證。

若以同一指標 $M$ 衡量兩種語言，可以另外報告語言落差：

$$
\Delta_{\text{lang}} = M_{\text{zh-TW}} - M_{\text{en}}
$$

必須同時列出 $M_{\text{zh-TW}}$ 與 $M_{\text{en}}$，不能只報 pooled score，否則英文樣本量較大時會遮住繁中的弱點。

翻譯英文資料不能直接取代繁中人類標註。翻譯可能消除或新增歧義，而英文標註者的分歧也不是繁中使用者的分歧。機器翻譯資料最多只能當 Embedding 的跨語壓力測試，不得當作繁中主證據。

### 正式研究問題與假設

主要研究問題：

> 在一筆資料只取得部分標註時，能否預測完整標註結果是否會出現分歧，並在固定複核預算下，比隨機或簡單分歧分數更早找出需要人工關注的項目？

子問題：

1. 只使用目前可見標籤的 entropy 與票數差距，可以做到多好？
2. 加入文字 Embedding 後，是否能找出「目前暫時一致，但後續可能出現分歧」的項目？
3. 英文與繁中是否呈現相似改善，或存在明顯語言落差？
4. 加入 annotator 歷史與圖結構後，GraphSAGE 是否穩定勝過非圖模型？
5. 模型增益是否足以抵銷資料需求、維護成本與可解釋性損失？

預先設定的假設：

| 假設 | 內容 |
| --- | --- |
| H1 | 可見標籤 entropy 會顯著勝過隨機排序 |
| H2 | 多語 Embedding 加上結構化特徵，會勝過只使用可見標籤統計的基準 |
| H3 | 在具備足夠重複 annotator 與連通圖結構時，GraphSAGE 可能進一步改善排序 |
| H4 | 英文模型的改善不能直接代表繁中；繁中結果需獨立成立 |

### 問題形式化

令第 $i$ 個資料項目為 $x_i$，標籤集合為 $\mathcal{C}$，完整標註集合為 $A_i$。類別 $c$ 在完整標註中的比例為：

$$
p_{ic}
=
\frac{\sum_{a \in A_i}\mathbf{1}(y_{ia}=c)}{|A_i|}
$$

其中 $y_{ia}$ 表示 annotator $a$ 對項目 $i$ 的標籤。使用正規化 entropy 表示完整分歧程度：

$$
H_i
=
\frac{-\sum_{c \in \mathcal{C}}p_{ic}\log p_{ic}}
{\log |\mathcal{C}|}
$$

$H_i=0$ 代表所有標註完全一致；越接近 $1$，代表標籤分布越分散。

主要二元目標先定義為是否出現任何分歧：

$$
z_i
=
\mathbf{1}
\left(
\left|\{y_{ia}:a\in A_i\}\right| > 1
\right)
$$

若探索後發現「任何分歧」的陽性比例過高或過低，才改用預先固定的高分歧門檻：

$$
z_i^{(\tau)} = \mathbf{1}(H_i \ge \tau)
$$

門檻 $\tau$ 只能由訓練集決定，固定後才可評估測試集。

部分觀測實驗中，只向模型揭露 $r$ 份標註，記為 $O_i$；其餘標註 $U_i=A_i\setminus O_i$ 全部隱藏。主要設定為 $r=2$。模型輸出風險分數：

$$
s_i
=
f_{\theta}
\left(
x_i,
O_i,
\text{history}(a),
G_{\text{visible}}
\right)
$$

其中 $G_{\text{visible}}$ 只能包含預測當下已可見的 annotation edges。測試項目的隱藏標註不得出現在特徵、統計或圖 adjacency 中。

### 階段目標

1. 固定主要情境：每筆資料已取得前兩份標註，系統要判斷是否值得安排額外複核。

3. 固定主要排序指標：`Recall@10%`。

## 階段 2：公開資料、繁中資料與授權調研

### 階段目標

找到真正保留「誰標了哪一筆、給了什麼標籤」的資料。只有聚合後 majority label 的資料不能支援 annotator–item 圖，也不能研究分歧形成過程。

### 英文主資料：TID-8

[`MichiganNLP/TID-8`](https://huggingface.co/datasets/MichiganNLP/TID-8) 是目前的第一候選。它整合八個具有真實分歧的英文語言理解資料集，涵蓋 NLI、情緒、仇恨言論與幽默等任務，並保留 annotator 與個別 annotation 的關係。[原始研究](https://aclanthology.org/2023.findings-emnlp.832/)

先調研三個候選子資料集：

| 子資料集 | 優點 | 風險 | 初步優先度 |
| --- | --- | --- | --- |
| Sentiment | 問題直觀、適合先做分類與分歧排序 | 分歧高度主觀，需確認 label schema | 高 |
| MultiDomain Agreement | 與 disagreement 主題直接相關 | domain 差異可能形成混雜因素 | 中 |
| GoEmotions | 標註量大、annotator 重複度可能較好 | 多標籤且類別多，超出期末專案範圍 | 低 |

TID-8 的總 Dataset Card 授權欄目前未完整標示，且每個子資料集有自己的授權與引用。不能因為 Hugging Face 可以下載就假設可以任意使用；必須追到原始來源逐一記錄。

> 上表的優先度是調研階段的判斷，已被實測推翻。GoEmotions 當初評為「低」的理由是多標籤且類別多，但 TID-8 收錄的版本已依原作者做法壓成 4 類單標籤，這個理由不成立；sentiment 則因目標退化與圖結構碎裂被排除。定案是 GoEmotions，數字與理由見「子資料集定案」一節。

### 繁體中文資料策略

目前不把簡體中文資料或機器翻譯資料直接當成繁中主證據。優先順序是：

1. 搜尋保留穩定 annotator ID 的繁體中文多標註分類資料。
2. 若沒有合適公開資料，建立 150 至 300 筆繁中 pilot。
3. 每筆至少 3 位標註者，形成約 $450$ 至 $900$ 份 annotation。
4. Pilot 題目必須貼近論文主要使用情境，不能只為了方便而選與產品無關的情緒分類。
5. [`YACLC`](https://github.com/blcuicall/YACLC) 等中文多標註資料可作方法備援調研，但它是中文學習者語料且任務不同，不能取代臺灣繁中 pilot。

### 資料探索要計算的內容

對每個候選資料集建立以下統計：

- 唯一 item 數、annotator 數、annotation 數。
- 每個 item 的 annotation 數分布。
- 每位 annotator 的 item 數分布。
- 類別分布與缺失標籤。
- 完全一致、部分分歧與高 entropy item 的比例。
- Item–annotator 矩陣稀疏度。
- 二分圖的連通分量數與最大連通分量涵蓋率。
- 只標一次的 annotator 比例。
- 重複 item、重複 annotation 與格式異常。

令 item 數為 $N_I$、annotator 數為 $N_A$、實際 annotation edge 數為 $|E|$，圖稀疏度可記為：

$$
\operatorname{Sparsity}
=
1-
\frac{|E|}{N_I N_A}
$$

- 至少 1,000 個英文可用 item。
- 每個 item 至少 3 份 annotation。
- 至少 10% item 有分歧。

- 授權與引用清單。

## 階段 3：建立雙語、部分觀測與無洩漏資料協議

### 階段目標

建立能模擬「已取得少量標註，要不要把這筆送去複核」的資料切分。這一階段的品質比選哪個模型更重要。

### Item-level split

以 `item_id` 分組切分：

$$
\mathcal{D}
=
\mathcal{D}_{\text{train}}
\cup
\mathcal{D}_{\text{val}}
\cup
\mathcal{D}_{\text{test}}
$$

$$
|\mathcal{D}_{\text{train}}|:
|\mathcal{D}_{\text{val}}|:
|\mathcal{D}_{\text{test}}|
=
70:15:15
$$

同一個 item 的所有 annotation 必須留在同一 split。不能逐 annotation 隨機切分，否則模型可能在訓練時已看過測試 item 的其他標註。

TID-8 已提供 annotation split 與 annotator split，但本專題的預測單位是 item，仍需重新驗證它的 split 是否符合 item isolation；不符合就自行建立 group split。

### 部分標註 reveal protocol

對每個 item：

1. 從完整標註中抽出 $r=2$ 份成為可見集合 $O_i$。
2. 其餘標註成為隱藏集合 $U_i$。
3. 只用 $O_i$ 與 training history 建立特徵。
4. 用完整 $A_i$ 計算 target $z_i$。
5. 因公開資料通常沒有可靠時間順序，重複多個 random reveal seeds。

報告中稱為「隨機部分觀測模擬」，不能寫成真實時間序列預測。

### 繁中 pilot 設計

- 樣本：150 至 300 筆繁中資料。
- 標註者：至少 3 位，最好 5 位。
- 每位標註者先閱讀同一份規範，再獨立作答。
- Pilot 前用 20 至 30 筆做校準，但校準討論後的資料不要直接混入正式測試。
- 同時保存原始 label、時間、規範版本與後續裁決，不只保存 majority label。
- 先計算 raw agreement、Fleiss' kappa 或 Krippendorff's alpha，了解任務是否真的存在可研究的分歧。

### 冷啟動測試

建立兩種測試情境：

1. **已知 annotator**：測試 annotator 曾在 training items 出現。
2. **未知 annotator**：測試 annotator 完全不在 training graph。

如果模型只在已知 annotator 有效，論文結論必須限定為「對既有標註團隊有效」，不能宣稱能直接泛化到新標註者。

### 洩漏檢查

禁止使用：

- Test item 的隱藏標註。
- Test item 的完整 entropy 或 majority label 作特徵。
- 用 validation 或 test annotation 算出的 annotator 歷史表現。
- 完整圖預訓練後再切 train/test。
- 將 target edge 放入 GNN message passing。
- 用完整資料調整 $\tau$ 或決定特徵。
- 「每題標註數」當特徵：GoEmotions 標註數從 1 到 5 不等，標註數變多代表這題當初被判定需要加標，等於洩漏答案。本專題只取恰好 3 份的子集，分母固定，不得混入其他標註數的 item。

### 階段產出

- 固定的 split manifest。
- Reveal seed manifest。
- 繁中標註規範與資料字典。
- 自動洩漏檢查測試。
- 英文與繁中各自的資料流程圖與樣本統計。

## 階段 4：建立最低基準線

### 階段目標

回答「完全不使用 Embedding 或 GNN 時，可以做到多好」。所有後續模型都必須在相同 split、相同可見資訊與相同 $K$ 下比較。

### Baseline 0：隨機排序

- 對測試 item 隨機排序。
- 至少執行 30 個 random seeds。
- 回報平均、標準差與 95% confidence interval。

### Baseline 1：可見標註規則

從 $O_i$ 計算：

- 可見標籤是否已分歧。
- 可見標籤 entropy。
- 最高票與第二名票數差距。
- 可見標籤種類數。
- 可見標註數。

這條基準非常重要：如果它已經足夠好，就沒有理由先上 GNN。

### Baseline 2：文字表面與 metadata

不使用預訓練 Embedding，只使用：

- 字元數與 token 數。
- 問號、否定詞、模糊詞與程度詞數量。
- 文本是否包含多句、引號或條件句。
- 類別、domain 與來源資料集。
- 可見標註統計。

模型使用 Logistic Regression、Decision Tree 與 Gradient Boosting；Decision Tree 主要用於解釋，最終比較以 Logistic Regression 和 Gradient Boosting 為主。

### Baseline 3：加入 annotator 歷史

只從 training items 計算：

- 歷史標註數。
- 各類別標註比例。
- 與同組其他 annotator 的歷史分歧率。
- 與 training majority label 的一致率。
- 覆蓋的 domain 數。
- 歷史資料不足指示值。

Validation 與 test annotator 的統計要用 training-only 或 out-of-fold 方式產生，避免 target leakage。

### 排序指標

設測試集排序後前 $K$ 筆為 $\operatorname{TopK}$，真正分歧集合為 $\mathcal{P}$：

$$
\operatorname{Precision@K}
=
\frac{|\operatorname{TopK}\cap\mathcal{P}|}{K}
$$

$$
\operatorname{Recall@K}
=
\frac{|\operatorname{TopK}\cap\mathcal{P}|}{|\mathcal{P}|}
$$

若測試集共有 $N$ 筆，分歧盛行率為：

$$
\pi
=
\frac{|\mathcal{P}|}{N}
$$

則相對於隨機抽查的提升為：

$$
\operatorname{Lift@K}
=
\frac{\operatorname{Precision@K}}{\pi}
$$

固定預算比例 $b$ 時：

$$
K=\lfloor bN\rfloor,
\qquad
b\in\{0.05,0.10,0.20\}
$$

主要指標固定為 `Recall@10%`，因為它直接回答「只能複核 10% 資料時，可以涵蓋多少真正分歧」。

### 階段產出

| 模型 | PR-AUC | P@5% | R@5% | P@10% | R@10% | Lift@10% |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Random | | | | | | |
| Visible entropy | | | | | | |
| Logistic Regression | | | | | | |
| Gradient Boosting | | | | | | |

完成條件是至少一個可訓練模型完整跑通，並確認重跑可以得到相同 split 與評估結果。

## 階段 5：多語 Embedding 與雙語模型比較

### 階段目標

驗證文字語意是否能在可見標註統計之外，辨識出較容易引發分歧的內容。

### 主模型與選配模型

主線使用 `BAAI/bge-m3` 產生英文與繁中 dense embedding。它是開源、多語且可本機執行，能避免公開英文資料與未來論文私有資料走不同技術管線。

若時間與 API 額度允許，再從 Voyage `voyage-4-lite` 或 Mistral `mistral-embed` 選一個作外部對照。兩個 API 不必同時比較，否則研究焦點會從複核排序偏成供應商評比。

Embedding 本身不會直接輸出分歧機率。完整模型是：

$$
\mathbf{e}_i
=
\operatorname{Embed}(x_i)
$$

$$
\hat{p}_i
=
\sigma
\left(
\mathbf{w}^{\mathsf{T}}
[\mathbf{e}_i;\mathbf{v}_i]
+b
\right)
$$

其中 $\mathbf{v}_i$ 是可見標註與 annotator 歷史的結構化特徵，$[\cdot;\cdot]$ 表示向量串接。

### 必做消融

| 實驗 | 文字 Embedding | 可見標註統計 | Annotator 歷史 | 語言欄位 |
| --- | ---: | ---: | ---: | ---: |
| E1 | ✓ | | | |
| E2 | | ✓ | ✓ | |
| E3 | ✓ | ✓ | ✓ | |
| E4 pooled bilingual | ✓ | ✓ | ✓ | ✓ |

模型至少比較：

- Logistic Regression。
- Gradient Boosting 或 XGBoost。
- 英文單語模型。
- 繁中單語模型。
- 英繁 pooled model。
- 英文訓練、繁中 zero-shot 測試，僅作探索結果。

### Embedding 工程調研

- 是否需要固定 pooling 與 normalization 方法。
- 1024 維向量是否直接輸入 Logistic Regression，或需要 PCA。
- 不同語言的向量 norm 與分布是否偏移。
- 繁中標點、全形字元與臺灣領域詞是否需要正規化。
- 長文本截斷位置是否會丟失造成分歧的上下文。
- Batch size、CPU／GPU 記憶體與推論時間。
- 模型版本固定、cache invalidation 與可重現性。

每筆快取至少保存：

```text

language
provider
model_name
model_revision
dimension
text_hash
created_at
embedding
```

- 是否含個資或機密內容。
- API 供應商是否保留輸入。

- 是否允許論文研究使用。
- 是否需要去識別化。

### 階段產出

## 階段 6：GraphSAGE 異質二分圖實驗（選做）

### 階段目標

在相同可見資訊下，驗證圖結構能否穩定勝過 Embedding 加傳統分類器。GNN 是待驗證方法，不是預設答案。

### 圖結構

建立兩種 node：

- `item`：特徵為文字 Embedding、長度、語言與 domain。
- `annotator`：特徵為 training-only 歷史標籤分布、分歧率、標註量與冷啟動指示。

建立 relation-specific edge：

```text
annotator --annotated_as_<label>--> item
item --rev_annotated_as_<label>--> annotator
```

使用不同 edge type 表示 label，可以避免最小版 GraphSAGE 完全忽略 edge label。PyTorch Geometric 的 [`HeteroData`](https://pytorch-geometric.readthedocs.io/en/latest/notes/heterogeneous.html) 可分別保存不同 node 與 edge type，也支援將 GraphSAGE 轉成異質圖模型。

### 最小模型

- 兩層 GraphSAGE。
- Hidden dimension 先測 64 與 128。
- Dropout 先測 0.2 與 0.5。
- Item node 輸出 disagreement probability。
- 使用 validation PR-AUC early stopping。
- 至少 5 個 model seeds。

GraphSAGE 的一層聚合可寫成：

$$
\mathbf{h}_i^{(\ell+1)}
=
\sigma
\left(
\mathbf{W}_1\mathbf{h}_i^{(\ell)}
+
\mathbf{W}_2
\operatorname{mean}_{j\in\mathcal{N}(i)}
\mathbf{h}_j^{(\ell)}
\right)
$$

處理類別不平衡時，可使用帶正類權重的 binary cross-entropy：

$$
\mathcal{L}
=
-\frac{1}{N}
\sum_{i=1}^{N}
\left[
w_{+}z_i\log \hat{p}_i
+
(1-z_i)\log(1-\hat{p}_i)
\right]
$$

### 公平比較要求

| 模型 | 文字 | 可見標註 | Annotator 歷史 | 圖結構 |
| --- | ---: | ---: | ---: | ---: |
| Logistic Regression | ✓ | ✓ | ✓ | |
| Gradient Boosting | ✓ | ✓ | ✓ | |
| GraphSAGE | ✓ | ✓ | ✓ | ✓ |

三個模型必須使用同一批 item、同一 reveal seed 與相同可見資訊。

### GNN 特有洩漏風險

- Test item 的 hidden edges 不得進圖。
- Target edge 不得參與 message passing。
- 不得先用完整圖學 embedding 再切 split。
- Test item 若沒有可見 edge，模型只能依賴 item features。
- 未知 annotator 不可只靠 training 中學到的 ID embedding。

### 停損條件

若 GNN 符合以下條件，才值得在結論中列為候選：

- `Recall@10%` 平均提升至少 3 個百分點。
- 5 個 seeds 中至少 4 個勝過最佳非圖模型。
- Paired bootstrap 的改善不是明顯不穩定。
- 推論與維護成本仍符合未來 Label Suite 情境。

若不符合，正式結論就是「圖結構沒有提供足以抵銷複雜度的穩定增益，應先採簡單模型」。這仍然是完整且有產品價值的研究結果。

## 階段 7：穩健性、雙語誤差與失敗案例分析

### 階段目標

確認結論不依賴單一 random seed、單一 reveal 結果、單一語言或單一複核預算。

### 穩健性矩陣

| 維度 | 測試值 |
| --- | --- |
| Reveal 數量 | $r\in\{1,2,3\}$ |
| 複核預算 | $b\in\{0.05,0.10,0.20\}$ |
| 模型 seed | 至少 5 個 |
| Reveal seed | 建議 10 個 |
| 語言 | 英文、繁中、pooled |
| Annotator | 已知、未知 |
| 特徵 | text only、metadata only、combined、graph |

### 統計方法

- 以 item 為單位做 paired bootstrap。
- 回報平均、標準差與 95% confidence interval。
- 不只呈現最佳 seed。
- 所有模型在同一 bootstrap sample 上比較。
- 樣本數太小時，不把很小的數值差異解讀成模型優勢。

### 雙語錯誤分析

英文與繁中各抽查：

- 30 個 false positives。
- 30 個 false negatives。
- 20 個高信心正確案例。

錯誤類型至少區分：

- 文字本身有多種合理解讀。
- 缺少前後文或外部知識。
- 否定、反諷與條件句。
- Label schema 邊界不清。
- 少數 annotator 的系統性偏好。
- 臺灣用語、繁簡差異或領域術語。
- Embedding 截斷或正規化問題。
- 模型只記住特定詞彙或 domain。

### 公平與倫理

- 不把 disagreement 直接稱為 error。
- 不將低一致率 annotator 自動標成低品質人員。
- 不以人口屬性作自動懲罰或排班依據。
- Annotator ID 必須假名化。
- 模型只排序 item，不自動裁決標籤。
- 需要人工檢查模型是否對特定語言、類別或 annotator 群體產生系統性偏差。

### 階段產出

- 穩健性矩陣。
- Paired bootstrap 信賴區間。
- 英文與繁中錯誤分類表。
- 代表性成功與失敗案例。
- 模型限制與適用條件。

## 階段 8：結果判讀、論文寫作與 Label Suite 銜接

### 階段目標

把模型比較轉成可以執行的產品與研究決策，而不是只留下最高分模型。

### 決策規則

| 實驗結果 | 結論與建議 |
| --- | --- |
| 可見 entropy 已經最好 | 先採透明規則排序，不導入模型 |
| Embedding 穩定提升 | 採 Embedding + 簡單分類器作候選 |
| GNN 顯著且穩定提升 | 等真實繁中平台資料累積後，再評估 GNN 導入 |
| 英文有效、繁中無效 | 不可直接導入論文目標情境；需補繁中資料或領域調整 |
| 模擬有效、真實資料無效 | 不宣稱可改善正式複核流程 |
| 所有方法都不穩定 | 暫不做自動排序，優先改善資料紀錄與標註規範 |

### Label Suite 未來資料需求

至少要能串起：

```text
project_id
item_id
task_schema_version
annotator_pseudonymous_id
assignment_id
annotation_id
label_payload
annotation_started_at
annotation_submitted_at
review_id
review_outcome
adjudicated_label
adjudication_reason
reviewer_pseudonymous_id
model_score
model_version
visible_annotation_count
```

必須保留評分當下已可見的標註版本，否則未來無法重建模型當時真正知道的資訊。也要區分複核原因是分歧、標註錯誤、規範問題、資料缺漏或其他原因；否則只能預測「分歧」，無法驗證是否真的節省複核成本。

### 論文章節

1. 問題背景與繁中使用情境，並宣告兩個貢獻：部分觀測下的複核排序，以及標註平台的資料需求規格。
2. 相關研究：Le-Wi-Di 與 annotation disagreement 文獻、複核排序、以及大語言模型在分歧預測上的現況與落差。
3. 問題設定：部分觀測、固定複核預算與 item-level split——與既有文獻的差異集中在這一章。
4. 英文公開資料與繁中 pilot。
5. 隨機、規則與傳統 ML baselines。
6. 多語 Embedding 模型。
7. GraphSAGE 選做模型，與零樣本 LLM 對照線。
8. Precision@K、Recall@K 與 PR-AUC 結果。
9. 雙語、冷啟動、消融與穩健性分析。
10. 對 Label Suite 的資料與流程建議（第二貢獻的主體）。
11. 錯誤分析、資料污染、倫理與限制。

### 最終交付物

- 可重現的資料處理與實驗程式。
- 固定 split 與 reveal manifests。
- 英文與繁中 Dataset Cards。
- 標註規範與資料字典。
- Baseline、Embedding 與選做 GNN 比較表。
- 雙語錯誤案例與信賴區間。
- 一頁產品決策摘要。
- 期末報告與簡報。

## 專題程式碼與 Repo 邊界

目前不必先拆成新 repo。期末專題仍定位成 Label Suite 的技術調研與離線原型，先把資料處理、設定、模型與結果放在獨立實驗目錄，避免未驗證模型直接成為正式功能。

符合以下任一條件時再拆 repo：

- 課程要求獨立交件。
- 需要獨立部署 demo。
- Python／PyTorch 依賴與 Label Suite 主程式明顯不同。
- 實驗已有自己的版本、資料下載與重現流程。

正式公開前另確認 Label Suite 程式碼授權、公開資料授權、繁中 pilot 的同意與去識別化方式，以及論文是否允許公開原始文字與個別 annotation。
