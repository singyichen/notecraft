# 第 2 週：PLA 與 Python 基礎

*Perceptron Learning Algorithm & Python Basics*

## PLA：感知器學習演算法（Perceptron Learning Algorithm）

### 感知器模型：向生物神經元借的一個決策規則

感知器（Perceptron）是最早、也最簡單的一種監督式學習分類器，由 Frank Rosenblatt 於 1958 年提出，靈感來自生物神經元「輸入訊號加總、超過閾值才會發射」的機制。給定一筆樣本的特徵向量 x，感知器先算出**加權總和（net input）**`z = w·x + b`——w 是每個特徵的權重（weights），b 是偏差項（bias unit），兩者合稱第 1 週定義過的**可訓練參數（trainable parameters）**。接著把 z 丟進一個**階梯函數（step function）**：z ≥ 0 輸出 +1，否則輸出 −1。這個階梯函數就是第 1 週術語表提到的**激活函數（activation function）**最原始的版本——雖然現代神經網路幾乎不再用它（不可微分，無法配合梯度下降），但它是理解「線性模型 + 非線性判斷」這個組合的起點。

從幾何角度看，`w·x + b = 0` 這個方程式定義了一個**超平面（hyperplane）**——在二維特徵空間裡就是一條直線。w 是這條線的法向量（決定傾斜方向），b 決定它離原點多遠。這條線把特徵空間切成兩半，落在哪一半就對應哪一個類別；感知器的訓練目標，就是找出一組能把兩類樣本正確切開的 w 與 b。

### 訓練規則：PLA 怎麼一步步找到那條線

PLA 是一個線上（online）、逐筆更新的迭代演算法：

1. 把權重 w 與偏差 b 初始化為 0（或隨機小值）
2. 逐一檢查每一筆訓練樣本 (x, y)（y 是真實標籤，+1 或 −1）：
   - 若目前的 w、b 能正確分類這筆樣本，不做任何更新，繼續看下一筆
   - 若分類錯誤，依更新規則調整參數：`w ← w + η·y·x`、`b ← b + η·y`（η 是學習率，最基本版本可以直接設 η = 1）
3. 重複整個資料集（一輪稱為一個 epoch，第 1 週定義過），直到某一輪完全沒有誤判樣本為止

更新規則背後的直覺很直白：如果一個正樣本（y = +1）被誤判成負類，代表目前的決策邊界「離它太近、把它推錯邊了」，於是把 w 往這個樣本的方向調——`w + y·x` 會讓下一次算出來的 `w·x` 變大，讓這個樣本更容易被判成正類；負樣本被誤判的道理相反。PLA 不會一次把邊界調到完美，而是每次只用「一筆答錯的樣本」推它一小步，逐步修正。

### 收斂定理與線性可分的限制

PLA 有一個重要的理論保證——**Novikoff 收斂定理**：只要訓練資料是**線性可分**的（存在一個超平面能把兩類完全分開），PLA 保證能在有限步內找到一組能完全分類正確的 w、b，且更新次數的上界與兩類之間的「間隔（margin）」有關——間隔越大，收斂需要的步數越少。

但反過來，如果資料**不是線性可分**（例如經典的 XOR 問題：兩類樣本呈對角交錯排列，任何一條直線都切不開），PLA 會永遠找不到能讓整輪都不誤判的參數，陷入無窮迴圈、不斷更新卻不收斂。1969 年 Marvin Minsky 與 Seymour Papert 在《*Perceptrons*》一書中正式指出這個侷限，是感知器研究一度停滯（第一次 AI 寒冬的起點之一）的關鍵原因；也正是這個侷限，催生了後面用**多層感知器（Multilayer Perceptron, MLP）**疊加非線性 activation function 來處理非線性可分問題的路線——呼應第 10 週要學的多層神經網路與深度學習。

### PLA 與課程其他概念的連結

PLA 的逐筆更新規則，其實是第 1 週定義過的**隨機梯度下降（SGD）**的一個特例：可以把它理解成對「感知器損失（perceptron loss，只計算被誤判樣本的 −y·(w·x+b)）」做次梯度下降——每次只看一筆誤判樣本、算一次梯度方向、立刻更新，形式上跟 SGD「每次只用一筆樣本更新」的精神一致。差別在於 PLA 用的階梯函數不可微分，嚴格來說沒有一個處處可微的 loss function 可以套標準梯度下降，這也是下一週要學的 **Adaline** 出現的原因——Adaline 把階梯函數換成連續的線性輸出，改用均方誤差（MSE）當 loss function，就能用真正的梯度下降訓練，是從 PLA 到現代神經網路之間承先啟後的一步。

## Python 基礎

### 變數、基本型別與運算子：程式的最小單位

Python 是動態型別語言：變數不用事先宣告型別，賦值當下直譯器就會依值決定型別，同一個變數名稱之後也能重新指向不同型別的值。最常用的基本型別有四種：**int**（整數）、**float**（浮點數）、**str**（字串）、**bool**（布林值 True / False），此外還有一個特殊值 **None** 表示「沒有值」。

運算子分三類：**算術運算子**（`+ - * / // % **`，注意 `/` 一律回傳 float、`//` 才是整數除法、`%` 是取餘數、`**` 是次方）；**比較運算子**（`== != < > <= >=`，回傳 bool）；**邏輯運算子**（`and or not`，用來組合多個條件）。型別之間可以用 `int()`、`float()`、`str()`、`bool()` 明確轉換，但不同型別直接運算（例如字串加整數）會直接丟出錯誤，不會像某些語言自動幫你轉。

輸出用 `print()`，輸入用 `input()`（回傳一律是字串，需要數值要自己轉型）。格式化字串首選 **f-string**：`f"總和為 {total}"` 直接把變數值內嵌進字串，比舊式的 `%` 格式化或 `.format()` 更直覺，也支援在大括號內做運算或呼叫函式，例如 `f"{price:.2f}"` 可以順便控制小數位數。單行註解用 `#`，說明「為什麼這樣寫」而不是「這行做了什麼」。

### 四種內建容器：先問「要不要改、要不要順序、要不要查得快」

Python 的四種基本容器差別不在「能裝什麼」，而在「你打算怎麼用它」。**列表（list）**是可變的有序序列，適合會一直增刪的暫存區——逐行讀檔時把解析結果 `append` 進去就是典型用法。**元組（tuple）**是不可變的有序序列，適合表示「一組固定的東西」，例如圖片的形狀 `(28, 28)`；因為不可變，它還能當字典的鍵。**字典（dict）**是鍵值對映射，適合「用名字查東西」，例如把欄位名對應到那一欄資料。**集合（set）**只裝不重複的元素、不保證順序，適合去重與取交集——想知道兩份名單重疊多少，`set(a) & set(b)` 一行就好。

### 索引與切片：之後所有資料索引語法的地基

Python 用 `0` 起算的索引取單一元素，用 `a[start:stop:step]` 取一段——`stop` 不包含在內，負數從尾端算起，三個位置都可以省略。所以 `a[:3]` 是前三個、`a[-1]` 是最後一個、`a[::2]` 是每隔一個取一個、`a[::-1]` 是整個反轉。

這段語法值得多花時間，因為它不只是列表的功能：之後 NumPy 的 `arr[2:5, 1]`、Pandas 的 `df.iloc[10:20]` 用的都是同一套切片（slicing）文法，只是從一維擴充到多維。先把「左閉右開」與負索引練成直覺，後面的布林遮罩索引也只是同一規則的延伸。

`if / elif / else`、`for`、`while` 是基本控制流程，Python 用**縮排**而非大括號界定區塊，縮排是語法的一部分而非排版習慣。搭配 `enumerate()` 可同時拿到索引與元素，`zip()` 可把兩個等長序列配對走訪。

### 函式與彈性參數：`*args` 與 `**kwargs`

用 `def` 定義函式、把重複邏輯收成一個名字，是讓分析程式碼不變成一坨的第一步。**參數預設值（default argument）**讓呼叫端只在需要時才覆寫，例如 `def load(path, sep=",")` 平常寫 `load("data.csv")` 就好。經典陷阱：預設值只在定義時算一次，別拿可變物件當預設值，慣例是寫 `None` 再於函式內建立。

`*args` 把多餘的位置參數收成 tuple，`**kwargs` 把多餘的關鍵字參數收成 dict。它們在資料科學程式碼中隨處可見，因為套件常要「把使用者給的額外設定原封不動轉交給底層函式」——自己包一個繪圖函式時把 `**kwargs` 丟給 matplotlib，使用者就能沿用它原本所有參數。呼叫端也能反過來用 `*`／`**` 把既有的 list、dict 拆開餵進函式（unpacking）。

### 匯入、環境隔離與互動式工作流程

`import numpy` 匯入整個模組並以模組名取用；`import numpy as np` 取一個慣用別名（`np`、`pd`、`plt` 幾乎是社群共識，照著寫別人比較好讀）；`from numpy import array` 只取出特定名稱。少用 `from x import *`——它會把一堆名稱倒進命名空間，同名衝突時很難追。

資料科學專案特別需要**虛擬環境（virtual environment）**，因為套件之間版本相依很緊：不同專案各自綁定不同版本的 NumPy 或深度學習框架，全裝在同一個系統 Python 底下遲早互相踩到。用 `venv` 或 `conda` 為每個專案建獨立環境，再以 `pip install` 裝套件並把清單記成 `requirements.txt`，別人才能重現同一份環境。

最後是工作流程的差異：寫 `.py` 腳本是「一次寫完、整份執行」，適合已定案的流程與可重用的工具函式；**Jupyter Notebook** 則把程式切成一個個 cell 分開執行，變數留在同一個核心（kernel）裡——載入一份大檔案花三十秒，之後就能在同一份資料上反覆試不同的畫圖與統計，不必每改一次就重跑。底層的 **IPython** 另外提供 `obj?` 看說明文件、Tab 補齊屬性、`%timeit` 量測執行時間、`%run` 執行腳本、`!ls` 下 shell 指令，這些以 `%` 開頭的稱為魔術指令（magic commands）。代價是 cell 可任意順序執行、狀態容易亂掉，得養成「重跑整份確認結果」的習慣。
