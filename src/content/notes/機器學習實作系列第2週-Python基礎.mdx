# 第 2 週：Python 基礎

*Python Basics*

## 本週摘要

### 四種內建容器：先問「要不要改、要不要順序、要不要查得快」

Python 的四種基本容器差別不在「能裝什麼」，而在「你打算怎麼用它」。**列表（list）**是可變的有序序列，適合會一直增刪的暫存區——逐行讀檔時把解析結果 `append` 進去就是典型用法。**元組（tuple）**是不可變的有序序列，適合表示「一組固定的東西」，例如圖片的形狀 `(28, 28)`；因為不可變，它還能當字典的鍵。**字典（dict）**是鍵值對映射，適合「用名字查東西」，例如把欄位名對應到那一欄資料。**集合（set）**只裝不重複的元素、不保證順序，適合去重與取交集——想知道兩份名單重疊多少，`set(a) & set(b)` 一行就好。

判斷法很簡單：要「按位置取用」就用 list／tuple，要「按名字取用」就用 dict，只在乎「有沒有這個成員」就用 set。dict 與 set 背後是雜湊表，查找幾乎與資料量無關；list 的 `in` 要從頭掃到尾，資料一大差別就很明顯。

### 索引與切片：之後所有資料索引語法的地基

Python 用 `0` 起算的索引取單一元素，用 `a[start:stop:step]` 取一段——`stop` 不包含在內，負數從尾端算起，三個位置都可以省略。所以 `a[:3]` 是前三個、`a[-1]` 是最後一個、`a[::2]` 是每隔一個取一個、`a[::-1]` 是整個反轉。

這段語法值得多花時間，因為它不只是列表的功能：之後 NumPy 的 `arr[2:5, 1]`、Pandas 的 `df.iloc[10:20]` 用的都是同一套切片（slicing）文法，只是從一維擴充到多維。先把「左閉右開」與負索引練成直覺，後面的布林遮罩索引也只是同一規則的延伸。

### 控制流程與列表推導式：把「怎麼做」壓縮成「要什麼」

`if / elif / else`、`for`、`while` 是基本控制流程，Python 用**縮排**而非大括號界定區塊，縮排是語法的一部分而非排版習慣。搭配 `enumerate()` 可同時拿到索引與元素，`zip()` 可把兩個等長序列配對走訪。

真正該練熟的是**列表推導式（list comprehension）**：`[x**2 for x in nums if x > 0]` 等價於開一個空列表、跑迴圈、加條件判斷、再 `append`，但只要一行。資料處理特別偏好它，因為這類動作幾乎都是同一個形狀——「對每一筆做同一件事，並篩掉不要的」。推導式讓程式碼直接長成這個形狀：一眼看到輸出什麼、來源是誰、篩選條件是什麼，不必在迴圈裡追累加變數的狀態。這種「描述結果而非描述步驟」的思路，正是後面 NumPy 向量化運算的預演；同樣寫法也適用於字典與集合推導式。

### 函式與彈性參數：`*args` 與 `**kwargs`

用 `def` 定義函式、把重複邏輯收成一個名字，是讓分析程式碼不變成一坨的第一步。**參數預設值（default argument）**讓呼叫端只在需要時才覆寫，例如 `def load(path, sep=",")` 平常寫 `load("data.csv")` 就好。經典陷阱：預設值只在定義時算一次，別拿可變物件當預設值，慣例是寫 `None` 再於函式內建立。

`*args` 把多餘的位置參數收成 tuple，`**kwargs` 把多餘的關鍵字參數收成 dict。它們在資料科學程式碼中隨處可見，因為套件常要「把使用者給的額外設定原封不動轉交給底層函式」——自己包一個繪圖函式時把 `**kwargs` 丟給 matplotlib，使用者就能沿用它原本所有參數。呼叫端也能反過來用 `*`／`**` 把既有的 list、dict 拆開餵進函式（unpacking）。

### 匯入、環境隔離與互動式工作流程

`import numpy` 匯入整個模組並以模組名取用；`import numpy as np` 取一個慣用別名（`np`、`pd`、`plt` 幾乎是社群共識，照著寫別人比較好讀）；`from numpy import array` 只取出特定名稱。少用 `from x import *`——它會把一堆名稱倒進命名空間，同名衝突時很難追。

資料科學專案特別需要**虛擬環境（virtual environment）**，因為套件之間版本相依很緊：不同專案各自綁定不同版本的 NumPy 或深度學習框架，全裝在同一個系統 Python 底下遲早互相踩到。用 `venv` 或 `conda` 為每個專案建獨立環境，再以 `pip install` 裝套件並把清單記成 `requirements.txt`，別人才能重現同一份環境。

最後是工作流程的差異：寫 `.py` 腳本是「一次寫完、整份執行」，適合已定案的流程與可重用的工具函式；**Jupyter Notebook** 則把程式切成一個個 cell 分開執行，變數留在同一個核心（kernel）裡——載入一份大檔案花三十秒，之後就能在同一份資料上反覆試不同的畫圖與統計，不必每改一次就重跑。底層的 **IPython** 另外提供 `obj?` 看說明文件、Tab 補齊屬性、`%timeit` 量測執行時間、`%run` 執行腳本、`!ls` 下 shell 指令，這些以 `%` 開頭的稱為魔術指令（magic commands）。代價是 cell 可任意順序執行、狀態容易亂掉，得養成「重跑整份確認結果」的習慣。

### 這些基礎會在後面接到哪裡

這一週學的不是為了「會寫 Python」，而是為了讓後面每一週的工具都看得懂。索引與切片會直接變成 NumPy 與 Pandas 的取值語法，只是維度更多、還能用布林條件當索引；dict 的「用名字取值」正是 DataFrame 依欄位名取一整欄的心智模型。推導式訓練出的「對整批資料做同一件事」，接下來會升級成向量化運算——意思相同，但改由 NumPy 在底層一次算完。函式與 `**kwargs` 會在封裝清理流程、呼叫 scikit-learn 傳超參數時天天用到；虛擬環境決定實驗能不能被重現；Jupyter 的互動節奏則是後續探索式資料分析（EDA）與調參的主要場域。這週不是獨立的 Python 課，而是先鋪好後面共用的地基。
