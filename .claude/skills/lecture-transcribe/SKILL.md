# Lecture Transcribe Skill

從課堂錄音產出逐字稿，並用它補足 `src/content/notes/` 裡對應週次的筆記。整個流程分三段：**轉錄**（機械性、可重跑）、**補筆記**（需要判斷，是這個 skill 的重點）、**精練**（把口語鋪陳刪掉；補完的初稿一定偏長，這一段不能省）。

## 何時使用

- 作者給一個 YouTube 連結或 `recordings/` 裡的音檔，並指定要補的筆記檔
- 作者只要逐字稿，不補筆記（只做「轉錄」段）

## 何時不使用

- 沒有音檔也拿不到（YouTube 影片沒字幕又下載不到）—— 直接告訴作者需要音檔，不要嘗試從瀏覽器錄音等變通方式
- 作者要的是「從投影片整理筆記」—— 那是一般筆記撰寫，不是這個 skill

## 前置需求（第一次用時裝一次）

```bash
brew install ffmpeg yt-dlp        # macOS
pip install sherpa-onnx numpy opencc-python-reimplemented
```

模型（SenseVoice 約 1 GB + Silero VAD）由腳本第一次執行時自動從 GitHub Releases 下載到 `~/.cache/lecture-transcribe/`，不放在專案內。

為什麼選 SenseVoice 而不是 Whisper：CPU 上約 8–10 倍即時速度（2.5 小時錄音約 8–10 分鐘），中文（含台灣口音、中英夾雜的術語）辨識品質足夠補筆記用，而且模型能從 GitHub 下載，不依賴 Hugging Face。

## 第一段：轉錄

### 1. 取得音檔

- **YouTube 連結**：先檢查有沒有字幕（`yt-dlp --list-subs URL`）；有的話直接 `yt-dlp --write-auto-sub --sub-lang zh-TW --skip-download` 拿字幕，可以省掉整段轉錄。沒有字幕就下載音訊：
  ```bash
  yt-dlp -x --audio-format m4a "URL" -o "recordings/lectureNN.m4a"
  ```
- **本機檔案**：mp3／m4a／mp4／wav 都可以，直接用，腳本內部會呼叫 ffmpeg 轉 16 kHz 單聲道。

`recordings/` 已在 `.gitignore`，音檔與逐字稿都放這裡，不會進 git。

### 2. 執行轉錄

```bash
python3 .claude/skills/lecture-transcribe/scripts/transcribe.py \
  recordings/lectureNN.m4a recordings/lectureNN-transcript.txt
```

輸出每行格式：`[分:秒] 文字`，時間是該段在錄音中的起始位置，方便回頭聽。長錄音建議背景執行（`nohup … &`）再 tail 進度，因為一次 shell 呼叫可能超時。

### 3. 檢查輸出

- 抽看開頭、中段、結尾各幾行，確認語言與內容正確
- 辨識常見的系統性錯字，補筆記時要靠上下文修正，**不要照抄**：「程式」→「城市」、「機器學習」→「積極／繼續學習」、「函式」→「韓式」、「參數」→「引數」、「超參數」→「超引數」、「迴圈」→「回圈」、「Python」→「拍森／開森」、套件名（NumPy／Pandas／Matplotlib／PyTorch）常被拆成音譯
- 下課、閒聊、個別同學問答（登入系統、選課等）不需要進筆記；但**課堂 Q&A 裡跟課程要求有關的回答**（例如「微積分要學到什麼程度」）要留

### 4. 檔名衝突

如果作者電腦上另有本機 Whisper 之類的程序也輸出到 `recordings/`，**先 `ls -la` 確認同名檔案是否已存在、由誰產生**，必要時改用 `-sensevoice` 後綴，避免互相覆蓋。

## 第二段：補筆記

目標是「教授講了、筆記沒有的都補進去」，而不是重寫筆記。

### 1. 先讀完整份筆記，再讀完整份逐字稿

兩者都要**從頭到尾讀完**才開始動筆——逐字稿裡的內容常常對應到筆記中間某個既有段落，先建立全貌才知道該補在哪。

### 2. 列出缺漏清單

逐段對照，把「逐字稿有、筆記沒有」的內容分類：

- **課程行政**：平台用法、作業規則、評分理由、放假調整、期末專題規範、下週預告、回家作業
- **老師對投影片內容的展開與比喻**：這是最有價值的部分，投影片只有一行的東西老師可能講了三分鐘
- **課堂 Q&A** 中跟課程有關的回答
- **老師自己的觀點與提醒**（「不要小看傳統機器學習」「不是所有問題都要用深度學習」這類）
- **投影片上有但老師這堂沒講到的部分**：在筆記對應處加一句「本堂課因時間關係未講到，老師預告下週示範」

### 3. 補進對應段落，遵守筆記結構

- 補在**既有的對應章節之內**，用「老師的補充」「老師對 X 的說明」之類的過渡句接在原段落後面；只有真正找不到歸屬的內容（例如課程平台用法）才新開 `###` 小節
- 用作者既有的語氣與格式：繁體、全形標點、術語中英並列、bullet 至少一到兩句完整的話；原本是散文段落的地方就用散文續寫
- `**術語（English term）**` 這種粗體若後面直接接中文（無空格、無標點），remark 不會把收尾的 `**` 當合法收尾，會照字面印出 `**`（根因見 [CLAUDE.md](../../CLAUDE.md) 工作慣例）；補文字含中英並列的粗體術語時，記得在 `）**` 後面留一個半形空格
- 保留老師的比喻與具體例子（背題庫、雙黃線、講話大聲 vs 可靠），這些是逐字稿相對於投影片的主要價值；但只留**能解釋概念**的，純笑點與離題不要進來（判準見「第三段：精練」）
- 老師說投影片有誤的地方，若讀者對照投影片複習時會被誤導就記下來；若正文寫的已經是正確版本（例如直接寫「51–100 筆是第二類」），就不必再提投影片寫錯
- **絕對不要動**：frontmatter 以外的 `import` 行、`{/* @ai-visualize … */}` 區塊、`<GeneratedFrame>` 元件、圖片路徑；補文字只在它們之間插入
- 更新 frontmatter 的 `updatedAt` 為今天；`description` 只有在新增了整個主題時才改

### 4. 不要放進筆記的東西

- 同學個人資訊（姓名、email、公司）、助教的姓名與 email——寫成「助教聯絡方式在 E3 公告」即可
- 純閒聊、設備故障、下課時間協商的細節——直接不要寫進來，不必「一句帶過」
- 逐字稿原文的錯字

### 5. 驗證後寫回

```bash
# MDX 可編譯（去掉 frontmatter 後用 @mdx-js/mdx 編譯，或直接 astro build）
npx astro check 2>&1 | tail -5
```

確認 `import`／`<GeneratedFrame>` 的行數與位置跟改前一致（`grep -n "^import\|^<GeneratedFrame\|^{/\*"` 前後比對），再寫回原檔。完成時用幾句話向作者列出補了哪些類別的內容，並提醒可刪除的中間檔（`.wav`、半成品 `.opus`）。接著進入第三段。

## 第三段：精練

補完的筆記幾乎一定偏長——逐字稿裡的口語鋪陳會整段跟著被寫進來。補完之後**一定要再做一次精練**，把「講出來很生動、寫下來卻沒用」的東西刪掉。第 1 週那次的結果是 33.4k → 30.3k 字（約 −9%），沒有損失任何知識點。

### 判準：這句話拿掉之後，讀者複習時會不會少學到東西？

**留下**（這些是逐字稿相對於投影片的全部價值）：

- **讓抽象概念變具體的比喻**：背題庫的聰明小孩（overfitting）、Dropout 的「腰斬／封印解開」、暗扛題庫當模擬考（驗證集）、雙黃線（測試集不可跨越）、「說話大聲就贏」（為什麼要特徵縮放）、總編輯與小編（為什麼要看懂 AI 寫的程式）
- **老師的判斷與提醒**：「不是所有分類問題都要用深度神經網路」「不要小看傳統機器學習」「調超參數不是擲骰子」
- **會影響行動的課程行政**：作業期限與 bonus、考試範圍與可否帶小抄、期末專題規範
- **老師的自我更正**：例如講完 one-hot 才想到順序型類別本來就該保留大小關係——更正本身就是知識點

**刪掉**：

- **純笑點與離題**：機器狗背機槍、AlphaGo 的「棋靈王」、「小火龍就是你了」、雙黃線的「科技執法拍照」、老師自嘲寫程式寫不贏 AI
- **一次性的課堂狀況**：下課鈴、廣播系統、老師的截圖跟現場畫面對不上
- **看著螢幕就會做的操作細節**：勾「建立桌面圖示」、擴充功能顯示 Install 代表還沒裝
- **已被正文吸收的投影片勘誤**、以及語氣填充詞（「坦白說」「這樣子 OK 好」「就這麼單純」）

**壓縮但保留**（第三類，也是量最大的一類）：老師講一件事會鋪陳三分鐘，寫下來只需要兩句。助教批改流程、期末專案說明、one-hot、蒐集 raw data、Dropout、No Free Lunch、標註成本、VS Code 安裝步驟都屬於這種——論點留著，前因後果的口語繞路拿掉。

判斷不掉的時候問：這是在**解釋概念**，還是只是**當時很好笑**？前者留，後者刪。

### 去重：同一件事不要講兩次

補筆記是分段進行的，很容易在不同章節重複同一個解釋。補完後全文搜一次重複的概念（第 1 週有兩處：Python 直譯式效能的取捨、「補國文不補數學」的比喻），保留最完整的那一處，其餘改成一句交叉引用（「已在〈X〉談過」）。

### 段落長度是簡單的偵測器

超過 400 字的段落回頭再看一次，通常是口語鋪陳沒收乾淨：

```bash
awk 'length($0)>400 {printf "%d (%d) %s\n", NR, length($0), substr($0,1,60)}' <筆記路徑>
```

（`prompt:` 與 `<GeneratedFrame>` 那幾行本來就長，跳過。）

### 改法：精確替換，不要用 sed

長中文段落用 `sed` 改極容易出錯。寫一支 Python 腳本，列出 `(舊字串, 新字串)` 配對，逐一 `assert s.count(old) == 1` 再替換，最後印出成功筆數與字數變化——一次跑完、可驗證、對不上時會明講是哪一筆。

### 精練後照樣要驗證

```bash
npx astro build 2>&1 | tail -5              # 必須 build 成功
grep -c '^import\|<GeneratedFrame' <筆記路徑>   # 數量要跟改前一致
```

向作者回報時給「原字數 → 新字數」加上刪掉的三類東西，不要逐條列出每一處改動。

## 已知限制

- 時間戳偶爾出現 `[00:00]` 或明顯異常值，是 VAD 分段邊界的問題，順序仍正確；腳本已做基本修正，但不保證全對
- 沒有語者分離，老師與同學的話會混在一起，靠上下文判斷
- 中英夾雜的英文術語有時會被音譯成中文，補筆記時還原成英文
